# 主线整合：书签、AI 功能与既有阅读 UI

## 目标

将已通过 fnOS 真机验证的书签功能并入主线，同时保留主线当前已经存在的 AI 服务、SQLite FTS、AI 弹窗、多轮对话、流式输出和既有阅读器 UI。整合后，书签与 AI 都从同一套主线资源构建，避免再次出现服务端、前端和 FPK 内容不一致。

## 当前状态

- 主线 `main` 存在未提交的 AI 与阅读器 UI 改动，不能使用重置、覆盖或整体回退处理。
- 主线已经包含 AI 配置、AI 检索、SSE 流式接口、AI 弹窗和问答 UI，但书签按钮仍是预留状态。
- `ai-chapter-retrieval-task1` 分支包含已完成的书签存储、API、定位恢复、Drawer/移动端入口、失败恢复和真机验收记录。
- 书签分支同时包含较早版本的 AI 相关提交，不能整体合并，以免覆盖主线当前 AI UI。

## 整合策略

采用“主线安全提交 + 选择性移植书签”的方式：

1. 对主线当前已存在的 AI/UI 工作建立安全提交，保留所有用户已有改动。
2. 从书签分支只移植书签所需的服务端、前端、测试和文档变更。
3. 对共享文件进行人工合并，以主线当前 AI/UI 为优先，再补入书签调用链。
4. 不改变 AI 请求协议、AI Key 存储边界、SQLite FTS 索引结构、阅读进度、划线和想法数据结构。
5. 书签数据只新增到当前用户的书籍状态中，按 `bookId` 隔离，不迁移或重写既有数据。

## 代码边界

### 需要移植或合并

- 服务端：书签存储校验、书签列表/新增/删除接口。
- 前端 API：`getBookmarks`、`createBookmark`、`deleteBookmark`。
- 阅读器：当前位置语义定位、书签状态切换、定位恢复和按钮状态同步。
- 面板：书签 Drawer、加载状态、失败恢复、移动端入口。
- 测试：书签存储、API、DOM、Playwright、单双页和连续滚动验收。
- 文档：书签接口契约、开发进度和主线整合记录。

### 必须保留主线版本

- AI 弹窗 DOM 与 Apple Design 风格。
- AI 设置、连接测试、清除 Key 和保存逻辑。
- 多轮对话、流式输出、停止生成和状态提示。
- AI 来源章节标注、低置信度提示、当前章节/全文检索策略。
- SQLite FTS 及其回退路径。
- 现有阅读排版、主题、标记、想法、目录和进度行为。

## 共享文件冲突规则

| 文件 | 处理原则 |
| --- | --- |
| `app/server/index.js` | 保留主线 AI 路由和错误处理，补入书签路由，不重复注册同一路径 |
| `app/server/storage.js` | 保留主线状态结构，补入书签字段和校验，不影响 highlights/notes/progress |
| `app/ui/core/api.js` | 保留 AI SSE/API 方法，补入书签方法 |
| `app/ui/index.html` | 保留 AI 独立弹窗和设置视图，补入书签脚本、面板入口及状态属性 |
| `app/ui/reader/highlights.js` | 保留 AI 和现有工具栏状态，补入书签可用性、激活态和 EPUB 判断 |
| `app/ui/shell/drawer.js` | 保留 AI 弹窗入口和现有面板映射，补入书签面板及移动端动作 |
| `app/ui/styles.css` | 保留 AI 弹窗视觉规范，合并书签面板样式，避免重置共享 token |
| `tests/*`、`e2e/*` | 合并测试，不删除已有 AI、阅读模式和回归覆盖 |

## 数据与运行时约束

- 只有 EPUB 且存在有效 `currentBookId` 时启用书签。
- 书签定位器必须包含安全的章节 `href`，以及锚点、文本上下文或页码中的至少一种。
- 书签请求失败时保留本地已知状态，并显示可恢复提示。
- AI 仍只读取当前书籍允许的检索片段，不把书签内容或其他书籍内容加入上下文。
- API Key 不进入浏览器持久化状态、用户阅读状态或响应 JSON。
- 不改变 SQLite 索引的目录权限、文件权限和自动重建策略。

## 验证计划

按以下顺序验证：

1. 静态结构检查和 `git diff --check`。
2. 核心 Node 测试：存储、API、AI 服务、FTS、生命周期。
3. DOM 回归测试：书签状态、定位恢复、AI 弹窗、流式解析和停止状态。
4. Chromium 测试：书库打开 EPUB、书签新增/删除/定位、AI 多轮和流式 UI。
5. 打包检查：版本、脚本、AI/书签资源、文档和文件哈希。
6. fnOS 真机：EPUB 书签、单页/双页/连续滚动、AI 配置、问答、流式停止和现有阅读功能回归。

## 非目标

- 本次不实现 AI 对话历史长期持久化。
- 本次不新增 mobi、azw3、PDF 的书签或 AI 专项适配。
- 本次不重做 AI 检索算法、不引入向量数据库、不修改用户数据迁移格式。
