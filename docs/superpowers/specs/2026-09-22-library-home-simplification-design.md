# 书库首页简化与分类入口设计规格

状态：调研完成，待用户确认后执行。本文只定义方案，不执行产品代码修改。

## 用户目标

书库首页只保留一个清晰的主入口“我的书籍”。“新建分类”紧跟在“我的书籍”之后，用户可以在同一页看到全部书籍和自己创建的分类。当前的“我的分类”和“按目录”不再作为首页切换选项，避免把书籍、虚拟分类和物理目录混在同一组控件中。

## 建议的信息结构

```text
书库
  书籍数量 · 分类数量                         重新扫描

我的书籍                                      新建分类
  [全部书籍网格，支持整理、排序和选择分类]

分类                                          管理分类（可选）
  [分类 A] [分类 B] [未分类]
```

- “我的书籍”是首页内容标题，不再是三段式切换器中的一个按钮。
- “新建分类”位于“我的书籍”标题的右侧或其后的同一操作行，不放进分类卡片或分类切换器。
- 分类是首页下半部分的普通内容区；点击分类卡进入分类详情，详情中保留“添加书籍”和“整理”。
- “未分类”保留为分类内容中的系统项，避免用户误以为书籍消失。
- “按目录”从可见 UI 移除。源目录元数据和服务端只读能力暂时保留，用于兼容已有状态、后续恢复或管理员诊断。
- 不再显示“我的分类”这个模式按钮；如需要章节文字，只使用“分类”作为内容区标题。

## 行为契约

### 首页

- 固定渲染全部可阅读书籍，顺序使用现有 `allBookOrder`，没有顺序时按当前书目补齐。
- 继续支持打开 EPUB、Markdown、TXT、重新扫描、整理拖拽、上移/下移、分类选择。
- 创建分类成功后直接打开新分类详情，避免用户还要寻找新分类。
- 分类为空时显示轻量空状态和“添加书籍”入口。

### 分类详情

- 顶部统一显示“返回书库”“添加书籍”“整理”。
- 返回动作直接回到首页，不再依赖恢复“我的分类”模式。
- 添加书籍使用现有 placement API；成功后保留选择器状态，允许连续加入；409 时刷新 revision 并保留重试入口。
- 分类排序仍使用现有组织 order API；只改变用户隔离的虚拟 JSON，不移动源文件。

### 旧状态兼容

- 保留 `collections`、`collectionOrders`、`bookAssignments`、`allBookOrder` 数据，不做删除和重命名迁移。
- 保留服务端 `viewMode` 的读取兼容，前端首页不再根据 `collections` 或 `source-folders` 切换主界面。
- 已保存的 `source-folders` 偏好在新 UI 中按首页展示；不再通过 UI 进入源目录浏览。
- 旧的 history route 若包含 `source` 或模式状态，首次加载时安全回到 root，并且不把路径写入 URL 或 history。
- 既有 API 不删除，避免旧 FPK 或回滚版本读取用户数据时失败。

## 视觉与交互

- 继续使用现有书库 surface、圆角、间距、字体和 Apple 风格按钮，不新增一套视觉系统。
- 首页只保留一层主要动作：重新扫描、新建分类、整理；减少三个模式按钮造成的认知分叉。
- 桌面端拖拽手柄即时激活；移动端长按手柄；普通点击始终打开书籍。
- 分类卡和“新建分类”按钮保持 44px 左右触控目标，分类区在移动端单列排列。
- 删除分类仍只删除虚拟分类，书籍回到未分类；不与移除首页入口绑定。

## 安全与稳定边界

- 不改 fnOS 授权目录、书籍扫描、`openBook`、阅读 URL、书签、标注、全文搜索、AI 会话和 AI 索引。
- 不接受前端路径、root、正文或 UID；继续使用当前用户隔离、revision 冲突校验、健康扫描检查和原子 JSON 写入。
- 隐藏源目录入口不等于删除源目录数据；不自动清理既有分类或历史状态。
- 组织 API 失败时继续显示全部书籍首页；首页渲染异常时保持旧 flat fallback。

## 参考调研

- [SortableJS README](https://github.com/SortableJS/Sortable/blob/master/README.md)：把 `handle`、`delayOnTouchOnly`、`touchStartThreshold` 和排序生命周期分开，适合保留当前桌面直拖、移动端长按的交互边界。
- [Calibre-Web shelf.py](https://github.com/janeczku/calibre-web/blob/master/cps/shelf.py)：加入书架、移出书架和书架内排序使用不同操作，成员归属与顺序独立保存，适合作为本项目“分类归属”和“顺序”分离的参考。
- [KOReader Bookshelf](https://github.com/AndyHazz/bookshelf.koplugin)：把书架作为首页浏览层，把进入 shelf、编辑 shelf 和书籍集合操作分开；其文件夹浏览仍属于文件浏览语义，不能与用户虚拟分类混为一个入口。

## 不在本次范围

- 不增加嵌套分类、多标签、智能分类、真实文件移动、批量删除、AI 自动归类。
- 不重写或删除服务端 `source-folders` 数据结构。
- 不引入第三方拖拽依赖；沿用现有 Pointer Events 实现。
