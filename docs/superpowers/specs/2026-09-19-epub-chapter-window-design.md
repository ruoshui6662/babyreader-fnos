# EPUB 章节窗口阅读设计

## 背景与结论

真实样本《吃的营养科学观》包含 126 个 spine 章节。当前实现会在打开时解压、清洗、内联并渲染全部章节，然后在一个连续的 CSS 多栏容器中计算全书分页。即使 DOM 插入拆成小批次，双页模式仍会在每次追加时重排已经存在的全文。在 12 倍 CPU 降速的 Chromium 复现中，20 秒后仅完成约 28/126 个章节，表现为设备端无响应。

本设计的目标是让低性能 fnOS 设备先获得可操作的首章，并把后续工作限制在当前章节。它不以“整本总页码”换取首屏卡死。

## 目标与非目标

目标：

- 打开 EPUB 时只读取 EPUB 容器、OPF、目录和首个可读 spine 项；首章完成后即可翻页、选择与划线。
- 每次 DOM 中只保留当前章节；双页计算、图片解码、划线覆盖层和布局重排只针对该章节。
- 章节按钮、页末/页首翻页、目录和 EPUB 内部链接均可异步换章。
- 阅读进度保存并恢复 `href`、锚点及该章节内的页码/滚动位置；既有服务端进度接口与高亮数据格式保持兼容。
- 为真实样本建立低性能回归：首章可交互，不等待 126 章全部渲染；双页能翻到下一章。

非目标：

- 不实现 EPUB 3 版面固定布局、脚本执行、音视频播放或全书搜索。
- 不承诺全书稳定总页数；总页数会随字体、窗口和每章布局变化。
- 不把真实用户 EPUB 复制到仓库、测试夹具或 FPK。

## 方案选择

选择“惰性解析 + 单章节 DOM 窗口”。备选的“每批只插一章”被拒绝，因为它仍使 CSS 多栏在每次追加时重排已有全文，复杂度和内存会随书长增长；“禁用双页”会回避而非修复同一根因。

## 数据流与边界

1. `openEpubArchive(data)` 只加载 ZIP 索引、container、OPF、manifest、spine 和 TOC/NCX；它返回可复用的 `EpubArchive`，其中每个 spine 项拥有稳定的 source path 与序号。
2. `loadEpubChapter(index)` 按需读取一个 XHTML 文件，执行现有 HTML/CSS 清洗与资源预算，再生成唯一的 `.epub-chapter` 节点。资源预算属于该书会话，避免跨章节重复内联同一大资源。
3. `renderEpubChapter(index, locator?)` 在替换 DOM 前递增 generation；过期异步结果不得写入 DOM。成功后只对当前章节执行一次分页测量、绘制高亮和定位恢复。
4. 导航层根据当前章节的 `pageGroup` 判断边界：章节内翻页仍走现有 `setPageGroup`；在末页点“下一页”则调用 `renderEpubChapter(index + 1)`，上一页同理。加载期间所有翻页/章节按钮禁用并显示“正在打开第 N/M 章”。
5. 目录和内部链接把 target path 解析为 spine index；加载完成后再寻找 fragment。找不到 path 或 fragment 时保留原页面并给出可见错误提示。
6. 进度仍存入既有 semantic-position JSON。`href` 是当前 spine source path，`pageNumber` 是章节内页码；恢复时先加载 `href` 对应章节，再执行既有锚点/文本上下文/页码回退逻辑。

## 状态与兼容性

新增/替换的前端状态：

- `epubArchive`：ZIP、manifest、spine、TOC、metadata 和共享资源预算。
- `epubChapterIndex` 与 `epubChapterCount`：当前章节及总章节数。
- `epubChapterLoading` 与 `epubRenderGeneration`：异步替换的加载状态和取消令牌。
- `epubChapters`、`epubHtml` 不再保存整书 HTML；最多保存当前章节 HTML 作为当前视图数据。

既有高亮记录中的 `chapterHref` 已是稳定章节路径，继续用于跨章节恢复。高亮绘制只针对当前章节；切换章节后从内存/服务端记录中筛选当前 `chapterHref` 重绘。导出仍读取全量高亮记录，不依赖当前 DOM。

顶栏进度显示改为“第 N/M 章 · P%”；分页状态显示当前章节内的页码。此变化是为消除虚假的全书 1/890 承诺。

## 错误处理与性能规则

- ZIP/OPF/目录错误：显示明确的 EPUB 解析失败提示，且不遗留 loading 状态。
- 单章读取或资源内联失败：保留当前可读章节，显示“无法打开第 N 章”，允许重试或返回上一章。
- 每次加载只允许一个生效 generation；用户连续目录跳转时，旧请求结果丢弃。
- 大资源限制维持单文件 8 MB、单书会话 48 MB；被跳过资源不得阻塞正文。
- 一次章节加载在 DOM 变更前后各让出浏览器一次，禁止全文 `innerHTML` 或全文 `chapters.join()`。

## 测试与验收

1. 单元/源代码回归验证：解析入口不构造整书 HTML，章节加载 API 只按 index 读取 spine 项，状态清理释放 ZIP 引用。
2. Chromium E2E：普通 EPUB 中章节内翻页、章节边界翻页、目录跳转、内部链接和 reload 恢复均保持可用。
3. 真实样本的本地可选 E2E：12 倍 CPU 降速下，首章在 8 秒内出现且操作可用；不等待 126 个章节；双页末页可进入下一章节。
4. 划线：在两个不同章节创建高亮，切换来回及 reload 后各自可见；导出包含两条而不要求两个章节同时存在于 DOM。
5. 完整门禁：`npm test`、`npm run check`、Chromium E2E、FPK 构建通过。真实 fnOS 安装测试由用户执行，不以桌面 Chromium 替代。

## 风险与回滚

章节页码不再是全书总页码，旧 progress 的 `href` 为空时会回退首章。若某些 EPUB 的目录路径不在 spine，目录项将显示现有的“无法跳转”提示而不会卡死。该改动仅在前端解析/渲染层，不改变书库、权限、服务端存储或用户文件；回滚可恢复到当前整书渲染实现。
