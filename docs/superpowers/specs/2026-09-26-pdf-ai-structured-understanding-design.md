# PDF AI 结构化理解优化设计

## 1. 背景与问题

BabyReader 当前 PDF AI 已形成可信的基础链路：授权文件经 PDF.js 提取逐页文本，写入本地 SQLite FTS；服务端按问题检索有限片段，验证页码与文件指纹后才发送给已配置的 AI 服务，并把模型引用重新映射为可点击页码。

这套实现适合“某个概念在哪一页”“作者如何定义某术语”等局部查找，但仅靠问题关键词挑选最多 6 个片段，难以稳定回答学术论文常见的整体问题：研究问题是什么、使用了什么方法、主要结论与局限是什么、两个章节如何衔接。根因不是模型上下文窗口不够，而是服务端缺少论文结构、跨章节代表证据和可复用的整篇画像。

## 2. 参考方案与取舍

参考项目：[dmoshehun-prog/learn-from-materials](https://github.com/dmoshehun-prog/learn-from-materials)。可借鉴的是方法论，不直接集成其 Agent Skill、Python 脚本、`.learnkb` 或 HTML 生成器：

- 先建立完整材料的结构地图，再回答整体问题；
- 来源位置必须可追溯，材料事实、推断、材料未覆盖内容要分开；
- 用内容哈希与版本号缓存中间产物，并执行覆盖检查；
- 扫描件或视觉内容无法可靠解析时明确标记需要 OCR/视觉复核；
- “快速概览”和“系统学习”是不同成本层级。

BabyReader 的场景是常驻 NAS 阅读器，不是离线教材生成工具。因此首版只移植以下最小闭环：本地结构地图、按需快速论文画像、问题意图路由、混合证据和引用完整性校验。不会复制上游代码；若后续确需复制任何实现，必须单独列出文件并保留 MIT `LICENSE`/`NOTICE` 要求。

## 3. 目标

1. 对文本型学术 PDF 建立页码可追溯的结构地图。
2. 对“整篇讲什么/方法/发现/局限”等问题，首次按需生成轻量论文画像，后续复用缓存以降低费用。
3. 对精确查找继续使用现有 FTS；对整体问题组合结构画像、结构相关页和 FTS 命中。
4. 回答中只允许引用服务端本次提供的页证据；论文画像中的断言也必须绑定页证据。
5. 所有新能力仅作用于 PDF，任何失败都退回当前 PDF FTS 问答；EPUB 请求、检索、缓存、提示词和 UI 行为保持不变。

## 4. 非目标

- 不做 OCR、公式理解、图表视觉问答、跨 PDF 问答或外部联网核验。
- 不在扫描书库、打开 PDF 或翻页时调用 AI 服务。
- 不上传 PDF 原文件、图片、NAS 路径或未入选的全文。
- 不生成独立学习网页、知识图谱编辑器或 `.learnkb`。
- 不让模型自行决定页码、章节边界或“已覆盖全文”。
- 不修改 EPUB 的章节理解、摘要缓存、AI 问书请求体或回答协议。

## 5. 核心架构

### 5.1 本地结构地图

PDF.js 在独立 worker 中读取 PDF 原生 outline，并以受限文本几何信息识别候选标题。输出仅包含物理页索引、标题、层级、来源类型和置信度；不保存字体对象或完整额外文本。

结构构建优先级：

1. 有效 PDF outline；
2. 高置信度标题候选；
3. 无可靠结构时退化为固定页窗，不发明章节名称。

所有页码内部为 0 基，用户显示与引用为 1 基。结构地图按 `bookId + sourceFingerprint + parserVersion + structureVersion` 缓存，原文件变化立即失效。

### 5.2 按需快速论文画像

只有用户提出整体、方法、发现、局限或跨部分比较问题，且结构化检索开关已开启时才构建画像。局部查找与选文问答不触发画像。

画像固定字段为：

- `researchQuestion`
- `method`
- `findings`
- `limitations`
- `sectionSummaries`
- `uncovered`

每一条材料事实必须携带服务端证据 ID；无法引用的条目丢弃或进入 `uncovered`，不能写入事实字段。画像按 UID、文件指纹、供应商地址、模型、解析器版本、策略版本和提示词版本缓存。缓存失败不阻止当前回答，写入使用原子替换、目录 `0700`、文件 `0600`。

### 5.3 问题意图与混合检索

服务端纯函数将问题分为：

- `selection`：用户明确选文；
- `lookup`：术语、人物、数字、页内事实；
- `paper_overview`：整篇主旨或研究框架；
- `method`：数据、样本、方法、实验；
- `findings`：结果、结论、贡献；
- `limitations`：局限、不足、未来研究；
- `comparison`：两个部分、方法或观点的关系。

`selection` 与 `lookup` 保持现有路径。其余意图使用结构相关页、画像条目和原始 FTS 命中共同组成证据；画像只帮助选证据和组织问题，最终回答仍须引用原始 PDF 页片段。

### 5.4 回答协议

回答区分三类内容：

- “论文明确说明”：必须有页引用；
- “基于证据的归纳”：必须有页引用并明确是归纳；
- “现有证据无法确认”：不得用常识补齐。

模型输出中的引用仍经过现有 `sanitizeAiAnswerCitations()` 和服务端来源映射。画像缓存不直接成为可点击来源，只有本次重新核验的原始页证据可以展示。

## 6. 成本与资源上限

- 结构提取完全本地执行，不调用 AI；结构节点最多 256 个、outline 深度最多 8、标题最多 160 字。
- 单次画像最多选择 6 个结构单元；发送原文总量最多 24,000 字符。
- 单次画像请求实际输入不超过 8,000 字符；较长论文最多 3 个 map 请求和 1 个 reduce 请求，总原文输入不超过 24,000 字符。
- 单个 map 输入最多 8,000 字符，reduce 输入最多 8,000 字符，画像输出最多 1,600 token，总截止时间 45 秒。
- 画像失败、超时、取消或引用不完整时不落盘，并立即退回现有最多 6 条、总计 4,200 字符的 PDF FTS 问答。
- 同一缓存键只允许一个在途构建；其他请求等待同一 Promise，不重复计费。

这些是首版硬上限。实际设备基准只能收紧，放宽必须重新评审隐私和成本。

## 7. UI 原则

不新增复杂的“快速/系统”模式选择。用户仍从现有“AI 问书”输入问题：

- 首次整体问题显示“正在分析论文结构，仅发送有限页片段”；
- 命中画像缓存显示“已使用论文结构”；
- 回退 FTS 时显示“结构分析不可用，已按页检索”；
- 页面引用沿用现有点击跳页且不关闭面板；
- 不展示内部置信分数、缓存键或模型工作流。

## 8. 安全与稳定边界

- 新功能由 `BABYREADER_ENABLE_PDF_AI_STRUCTURE` 控制，默认关闭。
- API 请求体保持不变；新增 SSE meta 字段必须可选，旧前端可以忽略。
- 不升级 `AI_FTS_SCHEMA_VERSION`，不重建 EPUB 索引，不把 PDF 画像写入现有 EPUB 摘要表。
- 所有 PDF 内容均视为不可信数据；结构标题、正文和画像不能改变系统提示或触发命令。
- 授权撤销、文件变化、UID 变化、切书、浏览器取消时停止后续调用，不保存结果。
- 删除书籍或删除对应索引时，同步清理 PDF 结构/画像缓存；清理失败只记录，不阻止书籍删除。
- 纯扫描、加密、损坏、文本顺序异常、多栏错序、公式/表格依赖等情况必须返回能力限制。

## 9. 验收标准

1. 合成论文的“研究问题/方法/主要发现/局限”页召回不得低于既有 FTS 基线；结构检索不得引入基线外的来源或伪造章节。
2. 离线夹具中，整体问题结构检索页召回应高于基线，且覆盖多个分散结构区间；该指标只衡量合成夹具页召回，不等于语义答案准确率。
3. 同一用户、同一文件、同一模型的第二次整体问题不重复构建画像；指纹或模型变化后缓存失效。
4. 选文和局部查找不触发画像调用；扫描、打开、翻页均无供应商调用。
5. 无文本、加密、超限、取消、撤权和结构低置信度均安全回退或明确报错，不保存半成品。
6. PDF 结构开关关闭时，网络 payload、回答路径和 UI 与当前版本一致。
7. EPUB 全套 AI 单元和浏览器回归通过，且测试证明 EPUB 从未进入新增模块。
