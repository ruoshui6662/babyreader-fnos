# AI 多轮对话与流式输出设计规格

## 目标

在现有书本内容驱动 AI 问答基础上，增加同一个 AI 浮窗内的多轮追问和流式回答，同时保持当前 OpenAI-compatible URL、模型、API Key 配置方式、书本本地检索、Markdown 安全渲染和单轮问答兼容。

## 本轮范围

- 应用侧维护一个临时 AI 会话历史；
- 每轮问题重新执行当前书本检索；
- 服务端新增 SSE 流式问答接口；
- 前端将单一回答容器升级为多条消息；
- 支持回答增量渲染；
- 支持停止生成、请求失败和连接关闭清理；
- 保留现有非流式 JSON 接口作为兼容和回退路径；
- 关闭 AI 浮窗或切换书本后清理临时会话。

## 非目标

- 不使用 `previous_response_id` 或 OpenAI 持久化 `conversation` 作为第一版会话存储；
- 不把会话历史写入用户阅读状态、localStorage 或服务端持久化文件；
- 不实施 Embeddings、向量数据库或服务端书本内容二次校验；
- 不实施 AI 配置测试连接、URL SSRF 防护、完整无障碍审计和 fnOS 真机验收；这些进入后续计划；
- 不改变标记、想法、导出、目录和阅读进度数据结构。

## 方案决策

### 会话历史

采用应用侧临时历史，最多保留最近 6 轮问答，并限制总字符数。每次请求都重新发送书本约束指令、当前问题、最近对话和本轮检索片段。这样兼容更多 OpenAI-compatible 服务，也避免在当前 `store: false` 语义下依赖供应商保存会话状态。

### 书本检索

检索始终针对当前问题、上一轮用户问题、选中文本和当前章节重新执行。回答历史只用于帮助 AI 理解追问，不作为书本事实来源。书本片段继续被标记为不可信数据，不能执行其中的提示词。

### 流式协议

新增 `POST /api/books/:bookId/ai/ask/stream`。服务端向浏览器发送 `meta`、`delta`、`done`、`error` 事件。上游 Responses API 的 `response.output_text.delta` 转换为 `delta`；`response.completed` 转换为 `done`。如果兼容服务返回普通 JSON，服务端转换为一个完整 `delta` 和 `done`，不破坏兼容性。

### 前端消息模型

AI 浮窗维护 `user` 和 `assistant` 消息数组。回答卡片按轮次渲染，每轮回答拥有自己的来源章节。增量文本进入当前 assistant 消息，使用 50～80ms 的批量 Markdown 渲染，避免每个 token 都触发完整 DOM 重绘。

### 中止与错误

流式请求使用 `AbortController`。请求期间发送按钮切换为停止生成；关闭浮窗、新对话、切换书本和新请求开始前都中止旧请求。已输出的文本保留，并显示“已停止生成”；网络或上游错误显示错误状态，不污染后续新对话。

## 安全边界

- API Key 继续只在服务端读取；
- 浏览器只接收脱敏配置状态；
- 会话历史和书本上下文继续受问题、片段数、片段长度和总请求大小限制；
- SSE 只输出回答增量和来源元数据，不输出 API Key、上游完整响应或内部错误堆栈；
- Markdown 增量渲染继续经过白名单清洗。

## 验收标准

1. 第一轮问题行为与当前版本一致。
2. 第二轮可以理解“为什么”“这是什么意思”“书中还有哪些例子”等追问。
3. 每轮回答都只使用当前书本检索片段作为事实依据。
4. 用户能看到回答逐步出现，而不是等待完整响应后一次性显示。
5. 流式过程中可以停止，停止后不会继续追加文本。
6. 关闭浮窗、切换书本和新对话不会混用旧会话内容。
7. SSE 不可用或兼容服务返回 JSON 时，能够安全回退。
8. 现有单轮、配置、Markdown 清洗、来源定位和阅读功能回归通过。
