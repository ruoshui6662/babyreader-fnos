# 阅读选区批注与全书笔记侧栏：设计与代码审查手册

## 1. 文档目的与结论

本手册为 BabyReader fnOS 的 EPUB 阅读器规划一套可落地的批注子系统：选中文字后的六功能工具栏（复制、马克笔、波浪线、直线、写想法、问 AI），以及可查看整本书全部标记和笔记的右侧抽屉。

结论：项目已经具备文本定位、标记绘制、编辑备注、按书持久化和右侧抽屉的关键基础，功能可行，且第一阶段不需要增加第三方依赖或新服务端读接口。最合适的做法是以现有 DOM Range 定位和 `highlights` 存储集合为兼容层，在其上新增“选区会话”“标注样式”和“全书笔记面板”。AI 是唯一需要另行配置服务端能力的部分，应与批注 MVP 分阶段交付。

本设计仅覆盖 EPUB。Markdown/TXT 当前没有稳定的章节定位器，也没有现成的持久化批注流程；把它们纳入同一版本会扩大范围，延后处理。

## 2. 用户目标、范围与验收口径

### 已确认目标

- 用户拖选或长按 EPUB 正文后，在选区邻近处看到六项工具：复制、马克笔、波浪线、直线、写想法、问 AI。
- 三种标记、想法和文本锚点在刷新、切换章节、切换单双页模式后仍能恢复。
- 右侧抽屉显示当前书的全部标记和想法，而非仅当前章节；点击任一条可跳到其原文。
- 右侧入口有清晰、稳定的位置，桌面端不再展示无法使用的“笔记”占位按钮。
- 不破坏当前 EPUB 单章节分页窗口、连续滚动、进度保存、多用户隔离和导出划线能力。

### 本期不做

- 社交公开想法、评论回复、热门划线、多人协同。
- 对 Markdown/TXT 做持久化选区标注。
- 将整本 EPUB 原文发送给 AI、内建具体模型供应商或保存 AI 对话历史。
- 重写现有书库、权限、EPUB 解压与分页算法。

### MVP 验收

1. 在滚动、单页回退和双页模式选择一段多行中文，均能打开工具栏并完成任一标记。
2. 同一段文本可创建不同样式；重载后样式、笔记、章节归属和点击跳转均正确。
3. 右侧“笔记”面板可筛选“全部 / 标记 / 想法”，展示当前书所有章节的条目并跳转。
4. 未配置 AI 时，“问 AI”显示明确不可用原因且不发网络请求；配置前不会伪造回答。
5. 所有现有高亮数据在迁移后按 `marker` 呈现，原有导出仍能导出文本与备注。

## 3. 当前代码审查

### 3.1 已有能力

| 能力 | 证据 | 结论 |
| --- | --- | --- |
| DOM 文本选区 | `reader/highlights.js` 的 `setupDomHighlightInteraction()` | 已监听鼠标、指针、键盘和触摸结束事件，可作为选区工具栏输入源。 |
| 稳定锚点 | `serializeDomRange()`、`rangeFromHighlight()` | 已同时保存节点路径、绝对文本偏移、前后上下文，且重复文本恢复有上下文校验。 |
| 视觉覆盖层 | `drawHighlightRects()` | 已把每个 `Range.getClientRects()` 矩形映射至文章坐标，并补偿分页 `scrollLeft`。 |
| 笔记字段 | `note`、高亮编辑器 | 当前每条划线已有 4,000 字备注，可直接演进为“想法”。 |
| 全书数据 | `loadHighlights()` | 客户端已拥有当前书的完整高亮集合；分页只挂载当前章不妨碍在侧栏列出其他章。 |
| 服务端持久化 | `storage.replaceHighlights()` | 具备输入限制、颜色白名单、用户隔离和原子状态更新。 |
| 右侧抽屉 | `shell/drawer.js`、`index.html` | 抽屉、焦点恢复、Esc、遮罩和面板切换均已实现。 |
| 回归基础 | `e2e/highlights.spec.js` | 已覆盖创建、重载、编辑备注、重复文本和双页可见性。 |

### 3.2 已规划的按钮位置：现状与结论

**已有技术位置，但没有完成产品规划。**

桌面端现有 `.reader-floating-toolbar` 固定在视口右侧中部（`right: 20px`、纵向 58px 宽工具带）。它从上到下为：目录、划线、导出、搜索、书签、笔记、AI、主题、设置。`btnNotes` 已经位于合适的“阅读内容操作”区域，且 `data-reader-action="openNotes"`、`data-reader-panel="notes"` 都已预留；但它和搜索、书签、AI 一样被禁用，抽屉中的 `readerPanelNotes` 只是占位文案。当前两个抽屉页签只有“目录”和“显示”。

推荐桌面端正式布局如下，复用 `btnNotes`，不新建第二个笔记入口：

```text
右侧固定工具带（从上到下）
  目录
  笔记（本书全部标记与想法，启用）
  导出
  ─────
  主题
  设置
```

- `btnNotes` 放在目录下、导出上；这是“阅读内容”层级，用户看完一段内容后可立即回顾整书笔记。
- `btnHighlight` 在选区菜单上线后保留为键盘/无鼠标兜底，但不应继续被理解为主要创建入口；它可留在工具带末尾或在后续版本隐藏为只读快捷操作。
- `btnSearch`、`btnBookmarks` 与常驻 `btnAi` 继续保持不显示或禁用，直到其各自有完整功能，不在 MVP 中占据视觉注意力。
- 抽屉页签改为“目录｜笔记｜显示”。点击工具带笔记按钮时打开抽屉并直接选中“笔记”。
- 移动端现有工具栏在 520px 以下会隐藏 `btnNotes`；MVP 需新增 `btnMobileNotes`，并用它替换移动端“划线”按钮。移动端标记由选区菜单完成，底栏更应保留全书回顾入口。

### 3.3 关键风险与整改要求

1. **两个历史选区路径并存。** `highlights.js` 的 DOM 路径是当前 EPUB 阅读主路径；`navigation.js` 和 `highlights.js` 还保留 epub.js iframe/CFI 选择逻辑，但当前 `renderEpubDocument()` 使用的是清洗后 HTML 挂载到 `#article` 的路径。新功能只扩展 DOM 路径，不在 iframe/CFI 分支继续增加能力；兼容分支单独登记后续清理任务。
2. **当前临时浮标只有 3 秒生命周期。** 写想法和 AI 不能依赖它；需要独立 `SelectionSession`，点击工具后即使浏览器清空选区也保留文本、Range 克隆和定位器快照。
3. **当前文本签名截断为 500 字。** 服务端允许 4,000 字，但 `selectedTextSignature()` 截断会弱化长选区恢复。批注记录应保存最多 4,000 个规范化字符；AI 另设更小、明确的请求上限。
4. **当前覆盖层是 `aria-hidden` 的按钮集合。** 一条跨行标记会生成多个按钮，既不适合键盘访问也不利于无障碍。新渲染层应是非焦点视觉层；可访问的编辑入口放在右侧笔记列表和想法编辑对话框中。
5. **保存方式是整集合替换。** `replaceHighlights()` 每次写回全书数组，客户端虽用保存队列避免本地乱序，但服务端没有版本冲突解决。MVP 可继续使用（上限 10,000 条），并在性能阶段增加 revision 或项目级 PATCH API。
6. **滚动模式为首批 3 章 + 后台追加。** 全书笔记列表立即可用，但点击尚未追加到 DOM 的条目不能只依赖 `scrollIntoView()`；必须提供“按定位器导航”的加载兜底。
7. **分页模式只保留当前章 DOM。** 这是性能设计，不是阻碍。侧栏跳转要先 `navigateToEpubChapter()`，等待分页稳定，再从锚点恢复 Range 和页组。
8. **菜单关闭逻辑过于单一。** 现有文档点击监听只判断事件目标是否等于单个浮标。新菜单须使用 `menu.contains(event.target)`，并在滚动、章节切换、阅读模式变化、Escape 和失焦时主动失效。

## 4. 目标架构

```text
浏览器 Selection
  → selection-menu.js：SelectionSession、定位、菜单、复制、动作分派
  → annotations.js：建立/编辑/删除 Annotation，序列化 Locator
  → highlights.js：兼容旧数据、恢复 Range、绘制样式覆盖层
  → user-state.js + api.js + storage.js：按书持久化
  → notes-panel.js：全书查询、筛选、章节标题、跳转和侧栏渲染
```

不引入框架。项目是全局函数式 Vanilla JavaScript；新文件沿用既有脚本加载顺序和 `setup...()` 初始化约定。

### 4.1 SelectionSession

```js
{
  id: "sel-...",
  bookId: state.currentBookId,
  chapterHref: "OPS/chapter-1.xhtml",
  text: "规范化后的选中文本，最多 4000 字",
  range: Range,                 // 仅本次即时标记使用
  locator: { ...domRange },     // 持久化与跨章节跳转使用
  anchorRect: DOMRect,          // 菜单位置
  rects: DOMRect[],             // 仅当前绘制预览使用
  createdAt: Date.now()
}
```

会话仅允许选区完全位于一个 `.epub-chapter` 内；跨章节、折叠、空白或超长选区显示原因并关闭菜单。所有动作先消费快照，绝不在按钮点击时重新读取 `window.getSelection()`。

### 4.2 兼容的 Annotation 数据模型

第一期不重命名服务端 `highlights` 集合，避免破坏既有状态和导出。逻辑上将其中每一项称为 annotation：

```js
{
  id: "br-hl-...",
  kind: "highlight" | "thought",
  style: "marker" | "wave" | "line" | "none",
  color: "yellow" | "green" | "blue" | "pink",
  chapterHref: "OPS/chapter-1.xhtml",
  locator: "{...dom-range...}",
  text: "原文",
  contextBefore: "前文",
  contextAfter: "后文",
  note: "用户想法；纯标记为空字符串",
  createdAt: "ISO-8601",
  updatedAt: "ISO-8601"
}
```

旧记录未含 `kind`、`style` 时，读取时映射为 `kind: "highlight"`、`style: "marker"`；不需要一次性数据迁移。`thought` 可以同时携带样式，默认 `style: "none"`，从而支持“只记想法”与“划线并写想法”。

### 4.3 样式渲染

- **马克笔**：复用每行矩形覆盖层，半透明背景色。
- **直线**：每行矩形底部绘制 2px 实线，颜色跟随标记色。
- **波浪线**：每行使用内联 SVG path 或 CSS data URI 在底部绘制波浪；不依赖 `text-decoration-style: wavy`，因为现有矩形覆盖层不能精确附着到原文字节点。
- **想法无样式**：不绘制正文背景，右侧列表中以想法图标和引用展示。

渲染必须按当前挂载章节过滤；分页模式的坐标继续加上 `article.scrollLeft`。页面翻转、缩放、ResizeObserver 结算、章节挂载完成后重绘当前章节。连续滚动后台每追加一个批次也重绘该批次中已存在的标记。

### 4.4 全书笔记面板

面板不扫描 DOM，而是读取 `loadHighlights()` 返回的当前书完整集合；这使分页模式未挂载的章节也能立即列出。

```text
笔记
12 条标记 · 4 条想法
[全部] [标记] [想法]   [章节/时间排序]
──────────────────────
● 第 1 章  马克笔
  “引用原文前两行……”
  我的想法摘要（如有）
──────────────────────
〰 第 6 章  波浪线
  “引用原文前两行……”
```

点击条目调用 `navigateToAnnotation(annotation)`：

1. 用 `chapterHref` 查 `state.epubArchive.chapterIndexByPath`。
2. 分页模式：等待 `navigateToEpubChapter(index)` 完成；滚动模式：若目标章尚未挂载，调用按章加载/跳转兜底，不能直接返回失败。
3. 调用 `rangeFromHighlight(annotation)` 恢复 Range。
4. 用 `navigateToSemanticTarget(range.commonAncestorContainer.parentElement)` 或 Range 首矩形计算所在页组。
5. `redrawDomHighlights()` 后为目标条目增加短暂 focus flash，供用户确认位置。

章节标题优先从 TOC 的 `target` 映射得到；无法映射时显示“第 N 章”。第一期只做本书查询、三种筛选和时间/章节排序；搜索、标签、批量操作、跨书笔记库留作后续。

### 4.5 写想法与 AI

“写想法”打开现有高亮编辑器的演进版：展示引用、样式选择和焦点自动进入备注输入框；确认时创建或更新 Annotation。取消不写入任何记录。

“问 AI”不是笔记存储动作。它打开 AI 面板，将以下最小上下文传给尚未实现的 `aiService.ask()`：`bookId`、章节路径、选中文本、前后各最多 500 字上下文和用户问题。默认不发送整书内容，不保存对话。未配置服务时显示“未配置 AI 服务”，并保留本地笔记功能完整可用。

## 5. 交互、错误与无障碍规则

- 选区菜单优先出现在选区首行上方；上方空间不足时显示在最后一行下方；左右距离视口至少 8px。
- Desktop 使用 `role="toolbar"`，每个动作带中文 `aria-label`；菜单不抢走正文选择的焦点，动作后把焦点恢复到原阅读器或新打开的对话框。
- Esc 先关闭选区菜单，再关闭抽屉；点击菜单内部不关闭，点击外部关闭。
- 抽屉内采用 `role="tablist"`、三个 `role="tab"` 与相匹配的 `tabpanel`；保留既有焦点圈定和返回触发按钮行为。
- 复制失败需明确提示，并尝试可控的临时 textarea + `execCommand('copy')` 降级；不能静默假报成功。
- 标记保存失败时，先保留本地可见状态并提示可重试；离开书架前 `flushPendingHighlightSaves()` 必须继续阻塞返回。
- 锚点恢复失败的列表项显示“原文位置已变化”，仍保留引用、笔记和编辑/删除入口，不能丢失记录。

## 6. 分阶段路线图

| 阶段 | 交付 | 依赖 | 预计工作量 |
| --- | --- | --- | --- |
| A | 选区会话、六项菜单、复制、现有马克笔兼容 | 当前 DOM Range | 2–3 人日 |
| B | 直线/波浪线、数据模型兼容、样式恢复 | A | 2–3 人日 |
| C | 右侧全书笔记面板、跨章节跳转、移动入口 | A/B | 3–4 人日 |
| D | 写想法工作流、编辑删除、导出格式升级 | C | 1–2 人日 |
| E | AI 服务适配、配置、安全与流式面板 | 独立服务决策 | 3–5 人日 |
| F | 性能、无障碍、真实 fnOS 设备验收 | A–E | 2–3 人日 |

建议先完成 A–D，形成完整本地批注闭环；E 必须在模型供应商、凭据保管方式和隐私策略确定后启动。

## 7. 未来演进与触发条件

- 当单书批注超过 2,000 条或状态文件超过 2 MB 时，将“全数组 PUT”升级为 `GET/POST/PATCH/DELETE /annotations` 与服务端 revision。
- 当侧栏条目超过 200 条时采用分批渲染（每批 50 条）或窗口化列表，避免一次创建大量 DOM。
- 当新增 Markdown/TXT 批注时，先设计其稳定文档版本指纹和段落定位器，不复用 EPUB `chapterHref`。
- 当支持 EPUB 版本更新/重新导入时，引入书文件 fingerprint，与 TextQuoteSelector + 上下文恢复结果一并报告失效记录。
- 当引入 AI 时，将供应商调用仅置于服务端，密钥不能进入浏览器或 FPK 静态前端资源。

## 8. 审查结论

该功能在当前项目中可行，且“右侧笔记按钮 + 右侧抽屉”已有明确的技术落点：`btnNotes` 与 `readerPanelNotes`。缺少的是产品内容、启用逻辑、三页签布局、全书数据视图和跨章节导航，而不是新的界面容器。最大的工程风险不是绘制波浪线，而是确保选区在点击后不失效、跨章节列表项能够导航、以及在滚动/分页两种 EPUB DOM 策略下保持同一定位契约。
