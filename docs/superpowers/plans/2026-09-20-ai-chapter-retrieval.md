# AI 章节专用检索策略实施计划

> 状态：仅规划，暂不执行
>
> 目标：在不改变现有普通问答、全书检索、流式输出、来源引用和本地回退稳定性的前提下，为“本章/本节/当前章节”类问题增加专用检索范围和内容覆盖策略。

## 1. 背景与当前代码结论

当前 AI 检索链路为：

```text
当前问题 + 选中文本
  -> 服务端 SQLite FTS5 全书检索
  -> FTS 候选 + 词法候选
  -> RRF 混合排序、去重和 5400 字符预算
  -> AI 请求上下文
```

当前章节信息已经存在：

- 前端通过 `state.epubChapterIndex` 获取当前 EPUB spine 索引；
- 请求通过 `chapter.index` 将当前章节传给服务端；
- SQLite `ai_chunks` 已保存 `chapterIndex`、`chapterHref`、`chapterLabel`、`startOffset`；
- EPUB 文本读取已经返回 `text` 和 `headings`；
- 当前实现只把当前章节作为排序加分，不作为检索范围过滤条件。

关键问题：

1. “本章主要讲了什么？”等问题缺少有区分度的关键词；
2. FTS 查询使用全书范围，泛化词可能命中其他章节；
3. 当前章节加分只有在候选本身命中时才生效，不能把当前章节内容纳入候选；
4. 前端本地回退会建立整本书索引，即使问题只要求当前章节；
5. 当前置信度按问题词覆盖率判断，不适合章节总结类问题；
6. 现有评测数据主要验证事实问题和跨章节问题，尚未验证“当前章节范围准确率”。

## 2. 稳定性原则

本计划必须遵守以下边界：

- 普通事实问题继续走现有全书 FTS + 词法混合检索；
- 全书总结问题继续走全书范围；
- 只有明确识别为章节或选中文本总结的问题才进入新策略；
- 不立即修改 SQLite 表结构，不强制重建已有索引；
- 不改变 `/api/books/:bookId/ai/search` 和流式问答的既有字段语义；
- 服务端自行识别检索意图，不能只相信浏览器传来的意图字段；
- 当前章节读取失败时，不静默退回全书；
- 新策略出错时，普通问题仍保留原有检索路径；
- 每个任务都先增加测试，再实现代码；
- 完成后必须通过既有全量回归和《吃的营养科学观》真实书籍验收。

## 3. 目标检索模式

### 3.1 `chapter_summary`

触发示例：

- 本章主要讲了什么？
- 这一章的核心观点是什么？
- 当前章节可以总结出哪些内容？

策略：

- 只使用当前 `chapterIndex` 的片段；
- 如果问题有明确关键词，先执行当前章节范围内的 FTS/词法检索；
- 如果问题是泛化总结问题，则执行章节覆盖采样；
- 最终仍受最多 6 个片段和 5400 字符预算限制；
- 来源章节默认只允许当前章节。

### 3.2 `section_summary`

触发示例：

- 本节讲了什么？
- 这部分的主要观点是什么？

第一阶段不直接伪造精确小节边界。若有选中文本，优先降级为 `selected_summary`；没有选中文本时使用当前章节范围，并标记为章节级而非小节级。后续如需真正小节级检索，再增加 heading offset 数据。

### 3.3 `selected_summary`

触发条件：存在选中文本且问题要求解释、总结或概括选中内容。

策略：

- 选中文本作为最高优先级证据；
- 可从当前章节选取少量相邻片段补充上下文；
- 不扩展到其他章节；
- 保留现有选中文本命中加权和来源引用逻辑。

### 3.4 `book_summary`

触发示例：

- 这本书的核心观点是什么？
- 整本书讲了哪些内容？

继续使用全书范围，但后续可单独增加全书覆盖采样。本计划只保证不被章节策略误拦截。

### 3.5 `normal_lookup`

普通事实、因果、定义、比较和跨章节问题保持当前实现，不改变召回范围和排序接口。

## 4. 推荐架构

建议增加独立的纯逻辑模块，避免继续把意图识别、范围选择和 FTS SQL 全部堆进 `ai-fts.js`。

建议接口：

```js
detectRetrievalIntent(question, selectedText) -> {
  intent: 'chapter_summary' | 'section_summary' | 'selected_summary' | 'book_summary' | 'normal_lookup',
  reason: string
}

resolveRetrievalScope({ intent, currentChapterIndex, selectedText }) -> {
  mode: 'chapter' | 'selected' | 'book',
  chapterIndex: number | null,
  allowAdjacentFallback: boolean
}

retrieveChapterCoverage({ rows, limit, contextCharBudget }) -> matches
```

推荐文件边界：

- `app/server/ai-chapter-retrieval.js`：意图识别、范围决策、章节覆盖采样；
- `app/server/ai-fts.js`：执行范围过滤查询，并调用章节检索模块；
- `app/server/ai-retrieval.js`：复用去重、预算和普通模式置信度；增加章节模式置信度；
- `app/server/ai-service.js`：增加章节总结约束提示；
- `app/server/index.js`：保持请求字段兼容，返回新的检索元数据；
- `app/ui/reader/ai.js`：本地回退只加载当前章节，章节模式不建立整本书索引。

## 5. 分阶段执行计划

### Task 1：增加意图识别和范围决策

目标：只增加纯函数，不改变任何实际检索行为。

先写测试：

- “本章主要讲了什么？”识别为 `chapter_summary`；
- “这本书的核心观点是什么？”识别为 `book_summary`；
- 有选中文本的“这段内容说明了什么？”识别为 `selected_summary`；
- 普通事实问题识别为 `normal_lookup`；
- 空问题、超长问题和中性问题不误判为章节总结。

实现内容：

- 中文表达归一化；
- 章节语义词和全书语义词使用有限、可审查的规则表；
- 明确全书语义优先于章节语义；
- 选中文本总结优先级高于章节总结；
- 不使用模型调用做意图分类，避免增加 Token 消耗和不确定性。

验收：纯函数测试通过，普通问题识别结果保持 `normal_lookup`。

### Task 2：增加当前章节范围检索

目标：章节模式只查询当前章节，不影响普通模式。

先写测试：

- 当前章节范围查询返回结果全部具有目标 `chapterIndex`；
- 全书模式仍可返回多个章节；
- 当前章节不存在时返回明确的 `none` 状态；
- 当前章节为空时不得自动退回整本书；
- SQL 参数使用绑定变量，不拼接章节索引。

实现内容：

- 在 `searchBook()` 增加 `retrievalScope` 或内部 scope 参数；
- 章节模式使用 `AND chapterIndex = ?` 做 SQL 层过滤；
- 当前章节有关键词时，在章节范围内运行 FTS + 词法混合检索；
- 现有普通路径保持原 SQL 和融合顺序；
- 返回 `intent`、`scope`、`fallback` 元数据，但保留 `matches`、`confidence` 原字段。

验收：现有 38 条问题的普通检索指标不下降，章节模式不会跨章节。

### Task 3：增加章节覆盖采样

目标：解决“本章主要讲了什么？”没有有效检索词的问题。

先写测试：

- 泛化章节总结问题可以获得当前章节的开头、中部和结尾内容；
- 片段不重复；
- 不超过 6 个片段；
- 不超过 5400 字符；
- 章节内容短时不会补入其他章节；
- 片段顺序稳定，重复运行结果一致。

实现内容：

- 从当前章节按 `startOffset` 排序读取候选片段；
- 优先保留带标题或章节开头的片段；
- 对剩余位置按章节进度均匀采样；
- 使用现有 `fuseRankedMatches()` 的去重和字符预算，或抽出共享选择器避免重复实现；
- 给结果附加 `retrievalSources: ['chapter-coverage']`，供置信度和调试使用。

验收：输入“本章主要讲了什么？”时，返回内容全部来自当前章节，且上下文覆盖不集中在开头一处。

### Task 4：调整章节模式置信度

目标：避免泛化章节问题被误报为“检索依据有限”。

先写测试：

- 当前章节有效且覆盖采样成功时，置信度为 `high` 或等价的章节充分状态；
- 使用相邻章节补充时为 `low`；
- 当前章节无内容时为 `none`；
- 普通问题继续使用原词覆盖率规则。

实现内容：

- `assessRetrievalConfidence()` 增加 retrieval mode 分支；
- 章节模式主要依据章节有效性、片段覆盖度和范围一致性；
- 不再用泛化问题的词覆盖率直接否定章节模式；
- 保留普通问题的低置信度保护提示。

验收：章节总结不出现不必要的“检索依据有限”，普通低匹配问题仍受到原有保护。

### Task 5：增加章节约束提示和来源边界

目标：让检索范围、模型提示和来源引用保持一致。

先写测试：

- 章节总结 payload 包含“只概括当前章节”的约束；
- 普通问题 payload 不出现不必要的章节限制；
- 章节模式上下文来源全部属于当前章节；
- AI 输出只引用实际提供和实际使用的片段。

实现内容：

- `buildResponsesPayload()` 根据 retrieval mode 增加章节约束；
- 章节模式的 source metadata 只生成当前章节；
- 相邻章节回退必须显式标记，不得伪装成当前章节；
- 不改变已有来源章节延迟显示和圈号超链接逻辑。

验收：回答结束后，来源章节与实际引用一致，不出现全书无关来源。

### Task 6：修正前端本地回退路径

目标：服务端 FTS 不可用时仍提供稳定的章节策略，并避免整本书扫描。

先写测试：

- 章节总结只调用当前章节文本读取；
- 普通问题仍可构建整本书索引；
- 本地章节回退结果不跨章节；
- 当前章节读取失败时显示明确状态，不静默使用整书内容。

实现内容：

- `retrieveAiMatches()` 根据服务端返回或本地识别结果选择模式；
- 增加当前章节临时索引或章节缓存；
- 仅在 `normal_lookup`、`book_summary` 必要时使用 `_aiIndex` 全书索引；
- 保持浏览器端无 SQLite 时的兼容性。

验收：关闭服务端 FTS 的模拟环境下，章节总结仍能正确工作，普通问答不退化。

### Task 7：建立章节专项真实问题集和评测指标

目标：让章节策略可以被量化验收，而不是只看截图。

在 `tests/fixtures/ai-retrieval-questions.json` 或单独 fixture 中增加：

- 章节总结问题不少于 8 条；
- 小节/选中文本总结问题不少于 4 条；
- 全书总结问题不少于 4 条；
- 普通事实问题和跨章节问题继续保留。

新增指标：

- `scopeAccuracy`：结果是否全部属于要求范围；
- `chapterSummaryCoverage`：是否覆盖章节开头、中部、结尾；
- `genericSummaryFalseChapterRate`：泛化总结跨章节比例；
- `fallbackRate`：发生相邻章节回退的比例；
- 原有 Recall@1、Recall@3、Recall@6、MRR@6、false recall rate。

验收目标：

- 章节总结的跨章节误召回率为 0；
- 普通问题原有指标不出现显著下降；
- 章节总结上下文总长度仍受硬上限约束。

### Task 8：全量回归和真实书籍验收

执行顺序：

```text
npm test
npm run test:core
npm run test:lifecycle
npm run test:e2e
npm run check
npm run check:portable
node scripts/evaluate-ai-retrieval.js --book "吃的营养科学观.epub"
```

真实验收至少覆盖：

1. 在第 6 章提问“本章主要讲了什么”；
2. 在第 6 章提问具体糖类问题；
3. 跨章节提问维生素 D、钙、磷关系；
4. 选择一段正文后提问“这段内容的核心观点是什么”；
5. 当前章节切换后再次提问，确认范围随章节变化；
6. 禁用或模拟 SQLite FTS 不可用，确认本地回退不跨章节；
7. 流式回答、停止回答、来源延迟显示和多轮历史全部回归。

fnOS 验收继续使用现有设备验收工具，重点增加：

- 章节总结范围检查；
- 当前章节切换后检索范围检查；
- SQLite 索引权限和生命周期检查；
- FTS 失败时服务仍可启动，AI 功能可明确降级。

## 6. 回滚与发布策略

### 代码回滚

- 章节策略应由内部模式分支隔离；
- 发生异常时仅回退到旧的 `normal_lookup`，不能影响阅读器和普通 AI 请求；
- 不在第一阶段修改 schema，避免旧索引无法读取；
- 若后续增加小节 offset 字段，再单独提升 schema version，并保留自动重建逻辑。

### 发布闸门

只有满足以下条件才允许进入 fnOS 真机验收：

- 普通问题回归全部通过；
- 章节模式跨章节误召回为 0；
- 来源章节与上下文范围一致；
- 流式输出和停止按钮无回归；
- FTS 不可用时本地回退仍可用；
- 没有新增必须手动配置的用户步骤。

## 7. 暂不纳入本计划的内容

- Embedding 或向量数据库；
- 每章持久化摘要缓存；
- 自动生成章节摘要并长期保存；
- MOBI、AZW3、PDF 的格式适配；
- OCR；
- 真实小节边界识别和 heading offset 索引；
- AI 索引管理器 UI。

这些功能可以在章节策略稳定后单独规划，避免同时改变检索范围、索引结构和文件格式适配边界。
