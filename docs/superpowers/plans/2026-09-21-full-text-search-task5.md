**Goal:** Build a reproducible FPK candidate for the completed full-text search flow and verify the release archive contains the expected UI, server, tests, and fnOS acceptance tool.

**Spec:** `docs/superpowers/specs/2026-09-21-full-text-search-design.md`

## Global Constraints

- The FPK must be built from a clean, identified Git commit and manifest version `1.1.1`.
- The package must include the independent search API, `ui/reader/search.js`, server/DOM regression tests, and `docs/fnos-device-acceptance.sh`; Playwright E2E sources remain repository-side because the FPK does not ship the dev-only E2E tree.
- Packaging must not alter the SQLite schema, AI route, AI settings, or existing user data paths.
- Device acceptance is not considered complete without x86_64 and ARM64 fnOS evidence; local packaging cannot substitute for it.

## Review Focus

- The FPK must contain the new search controller at the expected nested path, not only in the source tree.
- The package must expose the independent `/search` route and must not accidentally omit the server implementation.
- Build provenance must identify the exact commit and indicate whether the source tree was dirty.
- The acceptance script must be inside the package so device verification does not depend on manual file transfer.
- A failed or unavailable fnOS device must remain explicitly pending rather than being recorded as passed.
