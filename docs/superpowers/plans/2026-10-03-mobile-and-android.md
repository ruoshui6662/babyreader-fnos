# 手机体验与安卓客户端计划（2026-10-03）

## 目标与范围

优先做两样东西：飞牛 FPK 的手机体验，和一个安卓客户端。Docker 版暂时不做，只在服务端留好平台接口。

用户反馈的问题：

1. 手机上的目录、书签、标记与想法从底部弹出，不符合常规用法，应从左侧滑出。设置继续从底部弹出。
2. 安卓上的翻页功能太少，现在的翻页方式让人看不明白。
3. 手机书库排得太挤，书与书之间、书与屏幕两侧都太近。整体页面逻辑要参考微信读书，做得更美观、更简洁。

现状（390×844 截图）：

- 目录面板是占 88% 屏高的底部面板，内容只占上面一小块，下方大片留空。
- 书库每行 3 本，两侧边距 16px，列间距 16px。封面上印着格式标签，书名可能占两行。
- 翻页只分"左右翻页 / 上下滚动"两种。点击区域固定为左三分之一后翻、右三分之一前翻、中间呼出工具栏，没有任何提示。

## M1 阅读面板改为左侧抽屉（FPK）

范围：只改手机端的 `#readerDrawer`（目录 / 书签 / 标记与想法）。

**外形**

- 从左侧滑出，宽 `min(84vw, 360px)`，占满屏幕高度，适配刘海和底部安全区。
- 背景加遮罩，点遮罩或向左滑可以关闭。
- 打开和关闭用平移动画；系统开启"减少动态效果"时不做动画。

**内容**

- 顶部像微信读书那样显示书的信息：封面缩略图、书名、作者、阅读进度。
- 往下是"目录 / 书签 / 笔记"三段切换，再往下是列表。
- 列表占满剩余高度，打开时自动滚到当前章节。
- 去掉列表外面那层"卡片套卡片"，改成直接铺开的列表，行高 48px。

**不变的部分**

- 设置面板仍从底部弹出，维持现在的短面板加"更多设置"。
- AI 面板不变。
- 桌面端不受影响。

**测试**：更新现有关于手机底部面板的 E2E，新增"从左侧打开、遮罩关闭、滑动关闭、当前章节可见"。

## M2 翻页（FPK，以及客户端增强）

设置里的"翻页"分组改成图标加一句说明，不再只写两个词：

- **翻页方式**：左右翻页 / 上下滚动（保留）。
- **翻页动画**（仅左右翻页时可选）：平移 / 覆盖 / 无。
- **点击翻页**：
  - "左右分区"（默认）：点左侧后翻，点右侧前翻，点中间呼出菜单；
  - "全屏下一页"（单手）：点哪里都前翻，点中间呼出菜单，向右滑后翻。
- **左右滑动翻页**：开 / 关。
- **第一次进入左右翻页时**：在页面上叠一层半透明说明，标出三个点击区域，点一下就消失，以后在设置里可以重看。
- **只在安卓客户端里出现的选项**：
  - 音量键翻页；
  - 保持屏幕常亮；
  - 隐藏系统状态栏，沉浸阅读。

## M3 手机书库与页面（FPK，参照微信读书）

- **两侧边距**：从 16px 改为 20px。
- **书架网格**：
  - 每行 3 本，列间距约 18px，行间距约 28px；
  - 封面统一 3:4，圆角 4px，阴影更轻；
  - 手机上封面不再印格式标签；
  - 书名 13px，最多两行；作者 11px、灰色、一行，没有作者就不显示这一行。
- **页面结构**：从上到下是标题和搜索、"继续阅读"卡片、分类标签、书架，每块之间留出固定间距，不再挤在一起。
- **统计页和笔记页**：统一用同样的边距和卡片样式。
- **验收**：用 390×844 和 360×800 两种尺寸截图，对照参考图逐项检查。

## M4 安卓客户端（Capacitor）

推荐做成"远程加载"的壳：

- APK 里只有一个很小的启动页。用户填入 NAS 地址（例如 `http://192.168.1.10:5666`），之后应用直接在 WebView 里打开 `/app/zhenshu/`。
- 登录用飞牛自己的网页登录，WebView 会保存登录状态。
- 选这种做法的好处：
  - 界面和服务端始终是同一个版本，FPK 升级后客户端不用跟着升级；
  - 现在的登录与权限模型不需要改动。

原生能力通过一个很小的 JS 桥提供，界面用 `window.ZhenshuNative?.…` 检测是否在客户端里，浏览器中这些选项自动隐藏：

- 返回键：先关面板，再退出阅读，最后才退出应用；
- 音量键翻页；
- 保持屏幕常亮；
- 状态栏颜色跟随主题，沉浸阅读。

目录：`clients/android/`（Capacitor 工程）。

构建条件：需要 JDK 17 和 Android SDK。这台机器上目前没有，下载安装前要先取得用户同意。

以后可以做的：离线下载书籍、回家后同步进度，这需要服务端提供下载与同步接口。

## D0 Docker 预留（只留接口，不出镜像）

- 新增 `app/server/platform/`，提供三个接口：用户身份、可读书库目录、配置与数据目录。
- `fnos.js` 封装现在的实现（`x-trim-*` 请求头、`TRIM_DATA_*` 环境变量、`TRIM_PKGVAR`）。
- `generic.js` 先写一个最简单的版本：书库目录来自环境变量 `ZHENSHU_LIBRARY_ROOTS`，登录用现有的直连密码。现在只用于测试。
- 服务端其余代码只通过这三个接口拿数据。以后做 Docker 版只需要补完 `generic.js` 并写 Dockerfile。

## 顺序

M1 → M2 → M3，每完成一个阶段可以单独打包测试，版本号依次递增 patch。然后做 D0（与 M4 的登录方式无关，可以穿插进行），最后做 M4。
