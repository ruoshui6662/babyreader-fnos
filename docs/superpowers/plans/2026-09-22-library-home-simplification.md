# 书库首页简化与分类入口实施计划

状态：已执行，待 FPK 构建与 fnOS 真机安装验收。

## 后续界面修订（2026-09-22）

用户进一步明确首页结构：顶部同一排显示“我的书籍”及所有用户分类；选择分类后，在该排下方切换书籍内容。移除之前计划中的底部独立“分类”卡片区。“重新扫描 / 新建分类 / 整理”集中在书库标题右侧，并采用统一的次要按钮样式。

实现时修复分类详情添加书籍面板的 DOM 插入点：面板插入书格所在的分区，而非错误地将分区内部网格当成外层容器的直接子节点。

规格：[2026-09-22-library-home-simplification-design.md](../specs/2026-09-22-library-home-simplification-design.md)

## Task 0：冻结现有契约与迁移边界

状态：已完成。保留旧组织 JSON、`viewMode`、source projection 和后端 API；旧 source history 在前端安全回到 root。

目标：先证明移除首页选项不会损坏组织数据和阅读入口。

检查：

- 记录当前 `GET /api/library/organization`、`allBookOrder`、分类归属和 route history 行为。
- 为没有 `allBookOrder` 的旧 JSON 明确补齐策略，不在读取时覆盖原文件。
- 确认 `viewMode=flat|collections|source-folders` 的旧记录都能安全进入新首页。
- 继续保留服务端 API 与 source projection 代码，暂不做破坏性删除。

验收：旧用户分类、排序、书签、阅读位置和 AI 数据不变；损坏组织文件仍按现有 fail-closed 规则处理。

## Task 1：首页改为“我的书籍 + 分类内容区”

状态：已完成。

文件边界：

- 修改 `app/ui/library/organization.js` 的首页渲染和 route 分支。
- 修改 `app/ui/styles.css` 的首页标题行、分类内容区和移动端布局。
- 不修改 `app/server/library.js`、书籍扫描器和阅读打开流程。

实现：

- 移除首页 `.library-view-switcher` 三段式按钮。
- 固定显示“我的书籍”，接入现有 `allBookOrder` 和全部书籍整理逻辑。
- 在“我的书籍”标题后直接放置“新建分类”。
- 在书籍网格后渲染“分类”区，显示分类卡、未分类卡和空状态。
- 分类卡点击进入现有 collection route。

验收：首页不会出现“我的分类”或“按目录”按钮；全部书籍仍可打开、拖动、重新扫描和刷新恢复。

## Task 2：新建分类与分类详情入口重排

状态：已完成。

实现：

- 新建表单挂在“我的书籍”操作行之后，创建成功后直接进入新分类详情。
- 分类详情保留“返回书库”“添加书籍”“整理”。
- 返回首页使用安全 root route，清除旧的 `viewMode` 依赖。
- 连续添加书籍保持现有 revision 和错误恢复逻辑。

验收：新建分类后不经过“我的分类”入口即可看到；分类内可加入书籍、刷新后保留、返回后首页分类数量更新。

## Task 3：移除源目录与旧模式 UI，保留后端兼容

状态：已完成。

实现：

- 从首页和分类详情移除“按目录”入口及相关管理按钮。
- 旧 `source` history 状态安全回到 root；不在前端展示真实路径。
- 服务端保留旧 `viewMode` 值、源目录 resolver 和 API 结构，防止旧数据回滚不兼容。
- 如确认没有任何受支持入口依赖 source route，再单独评估清理前端死分支；本 Task 不删除后端数据能力。

验收：旧版本写入 `source-folders` 后，新版本显示正常首页；不出现路径泄露、空白页或无法返回书库。
