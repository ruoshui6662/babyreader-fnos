# 商业级阅读体验优化计划（参照微信读书、Apple 图书、掌阅、得到）

> 日期：2026-10-01。基线版本：v1.3.8。
> 目标：把 BabyReader 从“功能齐全”推进到“体验统一、细节到位”：阅读界面一致、设置直观、动效克制、品牌专业。
> 本文先列调研结论和现状审查证据，再给出分阶段任务。每项任务都写明验收标准；开工前需要用户确认的决定集中列在 §6。

## 1. 调研：优秀阅读软件坚持的原则

### 1.1 微信读书

- **界面让位于内容**：阅读页“整体简洁清爽，且全程无任何形式的广告”。操作栏平时隐藏，轻点页面才浮现。[1]
- **选中文字后的操作集中在一个浮层里**：长按选中句子后弹出浮层，可以复制、划线、写想法、查词典、分享、纠错。[3]
- **划线和想法可以回顾、可以统计**：能查看本月阅读时长、今年读了几本书、在哪些书里留下了划线、想法和书签，还能看一本书或某一章的热门划线。[3]
- **网页版**：可调字体、字号、边距和背景（如护眼黄）；有单栏和双栏两种模式；可一键导出读书笔记，导出内容自带书名、作者和章节信息。[2]
- **书架**：可以按阅读进度、推荐值、类别整理，支持分组和自定义排序；首页突出“最近打开的书”和“本周阅读时长”。[1]

### 1.2 Apple 图书（官方使用手册 [4]）

- **一个“主题与设置”面板集中所有外观选项**：
  - 字号用“大/小”两个按钮调；
  - 主题（如“安静”“粗体”）是整套预设；
  - 进入“自定义”才出现行间距、字符间距、词间距、页边空白的滑块和“两端对齐”；
  - 一键“还原主题”。
- **翻页方式可选**：卷页、快速淡入淡出、滚动；PDF 等固定版式可以打开垂直滚动。卷页会让页面随手指实时弯折，可以来回拖动。[5]
- **导航安全网**：从目录或搜索跳转后，页面左上角出现圆角箭头，可以“返回之前阅读的位置”，再点右上角的箭头回到跳转后的位置。按住“目录”左右拖动，可以快速翻阅全书。
- **自动保存位置**：手册写明阅读位置在关闭图书时自动保存，“因此无需添加书签”，书签只用于想再次回到的页面。
- **无障碍细节**：“逐行导读”会让其余内容变暗、突出正在读的一行；还可以开启粗体文本。

### 1.3 Apple 人机界面指南：动效 [6]

原文要点：

- “Add motion purposefully, supporting the experience without overshadowing it. Don't add motion for the sake of adding motion.”（有目的地加动效，不为动效而动效。）
- “Make motion optional.”（动效必须可选，不能是传达重要信息的唯一方式。）
- “Aim for brevity and precision in feedback animations.”（反馈动效要简短、精确。）
- “In apps, generally avoid adding motion to UI interactions that occur frequently.”（高频操作一般不要加动效。）
- “Let people cancel motion.”（不要让人等动画播完才能操作。）

### 1.4 掌阅与得到

- **掌阅**：首页先展示“书架”，然后才是“书城”，避免混淆；官方称加入了 27 项人性化设计，由专门的体验团队逐项优化；另有 PDF 重排和横屏阅读。[7][8]
- **得到**：这次没有检索到可靠的公开资料介绍它的电子书阅读器设计细节。本计划不引用未经证实的说法；如果需要，请用户提供截图或具体想借鉴的功能。

### 1.5 提炼出的设计原则

| # | 原则 | 来源 |
| --- | --- | --- |
| P1 | **内容优先，界面退后**：阅读时只有正文；工具按需浮现，用完即退 | 微信读书、Apple 图书 |
| P2 | **所有格式只有一种阅读模型**：EPUB、PDF、MOBI 共用同一套顶栏、工具栏、面板、选区菜单和进度表达 | Apple 图书（PDF 与图书共用菜单） |
| P3 | **设置直观、少而精**：常用项（字号、主题）放最前，用可视化的色块和“Aa”预览，不用下拉框；高级项折叠；随时可还原 | Apple 图书 |
| P4 | **导航有安全网**：跳转后可以一键返回；进度用读者能理解的话说（“本章还剩 N 页”） | Apple 图书 |
| P5 | **划线和想法是第一等公民**：选区浮层操作统一；笔记可回顾、可导出，带章节信息 | 微信读书 |
| P6 | **动效克制**：有目的、简短、可打断、高频操作不加动画，尊重“减少动态效果” | Apple 人机界面指南 |
| P7 | **品牌一致**：图标、站点 favicon、页面里的品牌标识是同一套图形，小尺寸也清晰 | 通用做法 |

## 2. 现状审查（v1.3.8，2026-10-01 在本地预览中逐项查看）

| # | 发现 | 证据 | 违背的原则 |
| --- | --- | --- | --- |
| A1 | **手机上打开书，目录面板是空白的** | 375×812 视口下 `#tocList` 中有 3 个目录项，“目录”标签已选中，但列表容器高度为 0、不可见 | Bug |
| A2 | **每次打开书都会自动弹出目录面板**，桌面上把正文压暗，手机上几乎遮住全屏 | 设置里“默认展开目录”默认是开 | P1 |
| A3 | **EPUB 和 PDF 的界面不统一** | EPUB 顶栏显示“1-2 / 5”“0% · 1/3”和章节跳转按钮；PDF 顶栏换成页码胶囊和缩放胶囊，样式不同；PDF 右侧工具栏没有“目录”和“划线”，按钮顺序也不同（EPUB 以“目录”开头，PDF 以“导出”开头） | P2 |
| A4 | **右侧工具栏有 9 个按钮**，信息过载 | 目录、划线、导出标记与想法、搜索、添加书签、标记与想法、AI、深色模式、显示设置。其中“划线”应由选区浮层完成，“导出”使用频率低，应放进笔记面板 | P1、P3 |
| A5 | **顶栏同时出现两种进度** | “1-2 / 5”（页）和“0% · 1/3”（百分比和章节）并排 | P4 |
| A6 | **显示设置像表单而不是阅读设置** | 背景、正文字体是下拉框；字号排在列表下方；没有主题预设，也没有“Aa”预览 | P3 |
| A7 | **正文默认用无衬线黑体**，章节标题带下划线 | 正文字体为 PingFang/雅黑，19px，行高 1.9；没有默认衬线（宋体）方案 | 阅读质感 |
| A8 | **跳转后无法返回**原来的位置 | 目录、搜索、笔记跳转后，没有“返回原处”入口 | P4 |
| A9 | **品牌不专业** | 图标是 AI 生成的卡通猫，深色发光背景，细节多，小尺寸下会糊成一团；`ICON_256.PNG` 实际是 1024×1024，和 `ICON.PNG` 是同一个文件（各约 1 MB）；网页没有 favicon；页面里的品牌只有文字“BabyReader” | P7 |
| A10 | **动效没有体系** | `styles.css` 里有 9 种不同的时长（90–760ms），缓动曲线写法不统一；没有统一的动效变量 | P6 |
| A11 | **样式层层覆盖，修改风险高** | `styles.css` 共 7315 行，98 处 `!important`，末尾多次追加“v2”式覆盖块；同一元素的样式分散在多处 | 工程风险 |

## 3. 合理性判断：先做什么、不做什么

- **先修复、再统一、后打磨**：A1 是 bug，A2–A5 影响每一次阅读，收益最大、改动最小，排在最前面。品牌和动效属于打磨，放在阅读体验之后。
- **样式先收拢，再大改视觉**：A11 不解决的话，后面每改一处都可能被某个覆盖块抵消。因此在阶段 1 先建立统一的设计变量（颜色、字号阶梯、间距、圆角、动效），新代码只用变量。旧代码随改动逐步迁移，不做一次性重写，避免大面积回归。
- **统一阅读外壳，而不是改造各个阅读器**：EPUB、MOBI（转成 EPUB 后阅读）和 PDF 继续各自渲染正文，只把外层的顶栏、工具栏、面板、选区浮层和进度表达统一成一套组件。这样改动集中在界面层，不碰分页、渲染和数据接口。
- **刻意不借鉴的内容**：
  - 社交功能（书友想法、组队、排行）：这是私有 NAS 应用，不需要；
  - 书城、付费、推荐；
  - 卷页翻页：网页端实现成本高，在桌面鼠标操作下价值有限，而且 Apple 的卷页有专利；
  - 听书：需要语音合成能力，单独评估，不放进本计划。

## 4. 分阶段任务

规模：S 约半天，M 约 1–2 天，L 约 3 天以上。每个阶段结束后跑一次完整回归（单元测试、结构检查、E2E、书库组织专项），然后打包发布一个补丁版本，请用户在 NAS 上验收。

### 阶段 0：修复与默认值（S，建议先发 v1.3.9）——已完成（2026-10-01，见 CHANGELOG_WORK.md）

| 任务 | 内容 | 验收 |
| --- | --- | --- |
| 0.1 | 修复手机目录面板空白（A1） | 375×812 下打开书再打开目录，能看到全部目录项并可点击跳转；新增移动视口 E2E |
| 0.2 | “默认展开目录”改为默认关闭（A2），已有的用户设置保留 | 新用户打开书直接看到正文；已手动打开该设置的用户行为不变 |

### 阶段 1：统一的阅读外壳（M–L，v1.4.0）——已完成（2026-10-01，见 CHANGELOG_WORK.md）

> 实施时的调整：1.1 设计变量只为本阶段新增组件建立（全面收拢留到阶段 2 改设置面板时一起做）；1.4 选区浮层两种格式原本就是同一个组件，改为新增“搜索”；PDF 的页码与缩放保留在顶栏胶囊中，未移到底部（相关 E2E 布局用例很多，收益不足以抵消风险）。

| 任务 | 内容 | 验收 |
| --- | --- | --- |
| 1.1 | 设计变量：颜色、字号阶梯、间距、圆角、动效时长与缓动，集中在 `:root` 和三种主题（A10、A11） | 新增和改动的组件只用变量；回归无视觉退化 |
| 1.2 | 统一顶栏：返回、书名、一种进度表达（EPUB/MOBI 显示“第 X 章 · 本章剩 N 页”，PDF 显示“第 X / N 页”），EPUB 和 PDF 同一布局（A3、A5） | 三种格式截图对比，顶栏结构一致 |
| 1.3 | 统一右侧工具栏，精简为 5–6 个：目录、笔记（书签和标记合并）、搜索、AI、显示设置；“导出”移入笔记面板，去掉独立的“划线”按钮（A3、A4） | 三种格式的按钮相同、顺序相同；PDF 有目录（来自 PDF 书签大纲，没有大纲时显示页码列表） |
| 1.4 | 统一选区浮层：复制、划线（选颜色）、写想法、搜索、问 AI，EPUB 和 PDF 相同 | 两种格式的浮层截图一致；现有划线和想法测试全部通过 |
| 1.5 | 跳转安全网：从目录、搜索、笔记跳转后，出现“返回原处”按钮，几秒内或下一次翻页后消失（A8） | E2E：跳转后点击返回，回到原来的页 |

### 阶段 2：阅读设置与排版（M，v1.4.1）——已完成（2026-10-01，见 CHANGELOG_WORK.md）

| 任务 | 内容 | 验收 |

### 阶段 4：可选增强（按需，逐项确认）

- 阅读统计（仅自己可见）：书库首页显示“本周阅读时长”和今年读完的书数；数据只存在本机的用户目录。
- 笔记导出为 Markdown：按章节分组，带书名、作者和章节信息，参照微信读书网页版。
- 逐行导读和粗体正文，参照 Apple 图书的无障碍选项。
- 按住目录快速翻阅全书，参照 Apple 图书。

## 5. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 样式覆盖层多，改一处影响别处 | 阶段 1 先建变量；每个阶段跑全部 E2E，并补三种主题、桌面和手机的截图对比 |
| 统一外壳时破坏 PDF 的选区和缩放 | PDF 渲染与文本层不改动，只替换外层组件；PDF 相关 E2E 必须全部维持现状 |
| 字体文件体积（思源宋体完整字库数 MB） | 优先使用系统字体；需要内置时按需加载子集字体，并评估包体积 |
| 现有 7 个长期失败的 E2E 用例掩盖新问题 | 阶段 1 开始前先排查这 7 个用例，修复或标注原因 |

## 6. 需要用户确认的决定

1. **正文默认字体**：保持黑体，还是默认改为宋体（衬线）？微信读书和 Apple 图书都把衬线作为常用阅读字体。
2. **图标方向**：
   - 保留卡通猫，但重绘为扁平、简洁的图形；
   - 抽象成“猫耳 + 书页”的几何标志；
   - 其他想法。
   我可以先各画 2–3 个 SVG 草案供挑选；如果要做最终商用品牌，建议请专业设计师定稿。
3. **翻页动画**：只做“滑动 / 淡入 / 无”（推荐），还是也要卷页效果？
4. **阅读统计**（阶段 4）要不要做？
5. **发布节奏**：按阶段 0 → 3 逐个发版，每个阶段都在 NAS 上验收后再进入下一阶段（推荐），还是合并成一个大版本？
