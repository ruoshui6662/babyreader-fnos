# 全书搜索完整性与结果续取开发计划手册

> **执行约束：** 本文是规划手册，不授权直接修改代码、构建或发布 FPK。实施前先审阅本手册及其对已批准搜索设计的增补；获准后由执行者按阶段实施，每阶段通过验收再进入下一阶段。

**目标：** 修复“全书搜索只能看到临近章节/结果不完整”的问题，确保全书结果可持续翻阅、点选命中位置准确，同时将每次请求的 CPU、内存、响应体与数据访问维持在明确边界内。

**现状基线：** 延续 `docs/superpowers/specs/2026-09-21-full-text-search-design.md` 与搜索 Task 1–5。当前实现基于每书 SQLite FTS5；搜索默认最多返回 20 条、接口上限 50 条，候选块读取上限为 2,000；接口仅返回 `truncated`，前端没有续取；导航没有使用 locator 的精确偏移。EPUB spine 是否造成实际漏章仍须用覆盖诊断验证，不能先入为主归因。

**设计方向：** 保留每书 FTS5 和阅读顺序，不提升为无界扫描、不另建索引；增加受约束的游标式结果续取，让 2,000 候选块成为“每请求工作预算”而不是全书永久截断点；使用 locator 精确定位；只有诊断证实 EPUB 章节漏入索引时才修提取边界。

**技术栈：** Node.js、现有 SQLite/FTS5、现有 fnOS 身份与 `findBook()` 授权路径、原生 DOM 与 Playwright 测试。

**关联设计：** `docs/superpowers/specs/2026-09-21-full-text-search-design.md`（实施前需补充本手册定义的分页响应和精确导航契约）。

## 0. 适用范围与明确非目标

本计划只处理当前打开书籍内的全文搜索完整性、分页、定位和经证实的 EPUB 章节提取缺口。保留 EPUB/TXT/Markdown 已有支持范围及当前搜索入口与 surface。

不在范围内：AI 检索/排序/提示词/供应商与会话、跨书库搜索、向量或模糊检索、全文内容上传、搜索历史、SQLite schema 大改、另建搜索索引、书籍文件修改、书签/标注/进度变更。搜索不得调用 AI API 或消耗 AI 配置、网络服务或 token。

## 1. 已知证据与待验证假设

代码检查记录（2026-09-22）：

- `app/server/book-search.js` 设置默认返回数 20、最大返回数 50、候选上限 2,000；按章节和源偏移排序，只读前 2,000 候选，并通过 `truncated` 报告被截断。没有 cursor 输入/输出。
- `app/ui/reader/search.js` 固定发出全书 `limit: 20` 请求；只根据 `truncated` 显示“仅显示部分结果”，无续取操作。
- `navigateToSearchResult()` 调用文本查找时只传入命中词，没有把 locator 的 chapter/source offset 传入 DOM 定位，因此同章重复文本可能定位到较早出现处。
- EPUB 搜索复用 `app/server/ai-fts.js` 建立的章节索引。`extractSpine()` / `readBookChapters()` 对 ZIP 文件、OPF manifest/spine 的解析边界需要针对真实 EPUB 变体验证；某些缺文件章节目前可能被跳过。
- 当前已存在纯搜索、API 与浏览器测试，但尚不足以证明“超过 20 条结果后可续取”“超过 2,000 候选后的命中可达”或“同章多次命中精确落点”。

因此将问题拆成三种独立故障模式：

1. **已索引但看不到后续结果：** 固定首屏 20 条与候选预算截断，没有续取。
2. **内容没有进入索引：** EPUB spine/相对路径/编码等解析导致章节缺失，需覆盖诊断确认。
3. **结果可见但跳错位置：** UI 忽略 locator 偏移，使用本章首次文本匹配。

测试须分别证明或排除，避免用扩大扫描范围掩盖索引缺章。

## 2. API 与游标契约（对现有 spec 的增补建议）

保持原路由和现有参数，增加可选 `cursor`：

```text
GET /api/books/:bookId/search?q=...&scope=book&limit=20&cursor=...
```

响应保留已有字段与 `results` 顺序，增加：

```json
{
  "hasMore": true,
  "nextCursor": "opaque-bounded-token"
}
```

`truncated` 在兼容期保留并等于 `hasMore`，不再表示“全书永久被截掉”，而表示“当前响应之后还有可续取结果”。无更多结果时 `hasMore:false`、`nextCursor:null`。旧客户端仍可读取原有字段；新客户端以 `hasMore/nextCursor` 为准。

分页规则：

- 默认每页 20 条，单页上限仍为 50；不允许客户端用更大的 limit 绕过预算。
- 每个 HTTP 请求最多扫描 2,000 个候选块（或更低的实测安全预算）；候选拉取按稳定阅读顺序 seek/续查，不得每页从全书开头重复扫描。
- 游标要保留足以继续处理的稳定位置：章节序号、块起始偏移、稳定行标识及块内命中序号/偏移。一个块包含多条命中时不能丢弃页尾剩余命中；重叠块不能重复返回命中。
- 搜索结束位置基于确定性顺序：章节序号、原文偏移、匹配偏移；同一全文查询的分页串接结果须与一次完整、有界参考扫描的顺序和集合一致。
- 游标绑定规范化查询摘要、book ID、scope/chapterIndex、索引 source fingerprint 和游标版本。游标有长度上限、类型/范围严格校验；不包含路径、正文、snippet、原始查询或完整 book metadata。索引版本变化时返回可恢复的“索引已更新，请重新搜索”错误，不静默跳过/重复。
- 游标不是授权凭据。每次续取仍重新执行 Gateway 身份认证、`findBook()` 与授权根校验。签名只在现有服务已具备合适密钥设施时采用；不得为分页引入硬编码密钥或新的弱密钥存储。
- 必须通过稳定 keyset/continuation 查询保证下一页不会从头重新计入同一 2,000 候选预算。若当前 FTS SQL 不能高效 seek，应在实现前给出执行计划/性能证据并选择最小改动；不得退化成每页全量扫描。

游标异常（空结构、超长、版本不符、查询/范围不匹配、越界位置）必须返回明确的 400/409 类安全错误，不泄漏索引路径或 SQL 错误。接口对搜索结果、snippet 与返回字段继续执行现有约束。

## 3. 安全、稳定与性能边界

### 开源实现参考与取舍

- [KOReader 全文搜索实现](https://github.com/koreader/koreader/blob/master/frontend/apps/reader/modules/readersearch.lua)采用有界结果量、分批呈现及可取消的搜索工作流。可借鉴“结果分页 + 长搜索可取消 + 查询状态隔离”，不照搬 Lua/移动端菜单结构。
- [Foliate 的 EPUB 搜索模块](https://github.com/johnfactotum/foliate-js/blob/master/search.js)与其[项目说明](https://github.com/johnfactotum/foliate-js)展示了跨 section 搜索的实现方向，同时提示全内容扫描可能很慢并需渐进加载。BabyReader 已有服务器端 FTS5，不应退回浏览器读取/扫描整本书。
- [SQLite FTS5 官方文档](https://www.sqlite.org/fts5.html)是查询与索引维护行为的基准。`optimize` 是索引维护操作，不应作为普通搜索请求的补救步骤；分页必须用可验证的有界查询，不能靠反复从头扫或增大候选上限。

这些参考用于借鉴交互及资源控制模式；本项目以现有 SQLite、fnOS 授权和共享索引生命周期为准，不引入上述项目的运行时依赖。

### 数据与授权

- 唯一数据源仍为调用者已获授权的单本书索引；不得按客户端路径打开任意 EPUB、SQLite 文件或任意 book ID。
- 路由的 64 位十六进制 book ID、Gateway 身份、`findBook()`、授权目录验证每页都必须执行。不得把首次请求的鉴权结果放进客户端游标以跳过后续授权。
- SQL 全部参数化；游标只解析为受限标量，不拼接 SQL 或文件路径。
- 不记录查询全文、游标、snippet 或书籍正文；诊断日志只记录匿名 book 标识摘要、索引 fingerprint 摘要、章节/块/命中计数、耗时及受控错误码。
- 沿用现有数据目录隔离、索引目录/SQLite 文件权限、原子发布和索引并发控制；分页不得改变共享 AI 索引内容或权限。
- 不向浏览器以外的服务发送书籍正文、查询或命中片段；无搜索网络请求。

### 资源与退化行为

- query 长度、limit、cursor 长度、候选块数、单条 snippet 长度和单次响应结果数均有显式上限；沿用已批准 spec 中 query 上限及 snippet 上限，不在实现中擅自放宽。
- 单次请求只处理有限候选，满足页大小或预算即停；空命中查询达到预算时也能返回可续取游标，防止 0 条结果但实际尚未扫描完的假终态。
- 用户关闭搜索、改写查询、切换书籍或 scope 时取消/废弃旧请求；旧响应不可覆盖新状态。加载更多使用同一 query generation，防止重复点击并发造成重复结果。
- 索引缺失、更新中、损坏或 FTS 不可用时返回受控错误；不得自动触发无界重建，也不得阻塞阅读或 AI 会话。
- 性能验收包含冷/热查询、长书、多结果和低命中查询；用执行计划与基准确认续页成本随页推进而非每次从头增长。先记录基线，再定设备阈值；不能只以开发机结果宣称 NAS 达标。

## 4. 文件边界与实现任务

### Task 0：搜索覆盖诊断与设计契约复核

**目的：** 定位具体用户书籍的结果缺失属于“未索引”“已索引但截断”还是“点选落错”。

- 给既有搜索测试添加可控的合成 EPUB：目录层级 href、相对路径、URL 编码、多个 spine item、manifest 中未进入 spine 的资源、空/缺失资源及末章唯一命中。检查索引章节计数和章节顺序，不输出 fixture 正文到日志。
- 增加只输出计数的诊断方式：解析出的 spine item 数、成功读取数、被跳过数及受控跳过原因；不能输出真实书名、路径或正文。诊断运行需明确目标 book ID 仍经授权校验，且默认不启用详细日志。
- 在测试夹具和代码边界中验证超 20 条、超过 2,000 候选、同块多命中、跨 chunk overlap、同章重复目标等现象。
- 根据诊断结果记录 EPUB 章节覆盖缺口是否复现。若没有可安全使用的实机书籍样本，只用合成 fixture，不要求用户上传书籍或内容。
- 将第 2 节契约作为对 `2026-09-21-full-text-search-design.md` 的增补提案；实施前复核兼容字段、游标有效期/索引变更错误与 seek 方案。

**边界：** Task 0 只新增/调整测试及本地诊断，不改变生产搜索逻辑，不读写用户书籍，不启用新的日志采集。

**验收：** 能以测试分别复现首屏截断、候选预算截断、跳错命中；章节解析夹具明确证明支持/不支持的 EPUB 结构；原有测试通过。

### Task 1：服务端有界游标分页

**文件范围：** `app/server/book-search.js`、必要时 `app/server/index.js`、`tests/book-search.test.js`、`tests/search-api.test.js`。

- 先写失败测试，再实现候选 keyset 续取、块内命中续取、overlap 去重与确定性排序。
- 增加并验证 `cursor` 参数及 `hasMore/nextCursor` 响应；保留旧 `truncated` 兼容语义。
- 确保每页预算是最多 2,000 候选块、输出最多 50 条，且预算耗尽但仍有后续候选时 cursor 推进。空命中页同样可续取。
- 重新认证并解析授权书籍；索引 fingerprint 不匹配时拒绝旧 cursor 并提示重新搜索。
- 对 malformed/tampered/oversized cursor、不同 book/query/scope 复用 cursor、负/过大行位置和 SQLite 错误添加测试。
- 用 SQLite `EXPLAIN QUERY PLAN` 与 benchmark 验证续页 seek；不接受 OFFSET 从头跳过全部此前候选的实现。

**验收：** 将多页结果拼接后与完整参考排序结果逐项一致；无重复、无遗漏；超 2,000 候选后仍可取得末段唯一命中；每次请求候选数、返回数受限；旧 API 客户端字段兼容；跨书/用户授权测试通过。

### Task 2：前端“加载更多”与请求生命周期

**文件范围：** `app/ui/core/api.js`、`app/ui/reader/search.js`、`tests/dom-regression.test.js`、`e2e/search.spec.js`。

- 搜索首屏仍请求默认 20 条；保存当前 query generation、cursor 和结果 identity。
- `hasMore` 时在列表尾部显示符合既有 Apple 风格的“加载更多”操作及单一加载状态，不将两个“正在搜索……”状态同时渲染；加载失败保留已有结果并提供可重试动作。
- 仅当响应属于当前书籍、scope 和 query generation 时追加；以稳定 result id 去重，维持服务端阅读顺序。
- 查询变更、关闭 surface、书籍/章节变化、scope 变化时清除 cursor 和旧结果并取消或忽略旧请求；禁用并发重复续取。
- `truncated` 仅作为兼容降级提示：旧服务端没有 `hasMore` 时仍显示明确的部分结果提示，不假装已有分页。

**验收：** 真实浏览器测试至少验证 45+ 命中可连续加载、无重复/乱序；查询切换时慢响应不污染新查询；加载失败后可重试；关闭/切书后旧响应无副作用；无 AI API 请求。

### Task 3：基于 locator 的精确命中导航

**文件范围：** `app/ui/reader/search.js`、必要的阅读定位 helper、`tests/dom-regression.test.js`、`e2e/search.spec.js`。

- 导航使用 `locator.chapterIndex` 与 `locator.offset/matchOffset`，加载目标章节后在可验证的文本节点范围中定位该次命中，而不是无条件查找本章第一个同名字符串。
- 明确服务端 offset 与渲染文本 DOM 的映射（HTML entity 解码、连续空白规范化、UTF-16 code unit、emoji/补充平面字符、块 overlap）。若原始字符偏移不能直接映射，服务端返回最小必要的局部上下文/命中序号作为辅助，并继续禁止返回整章正文。
- 无法精确恢复 DOM range 时才回退到章节起始或最近可验证位置，并显示非阻断说明；不能伪称已精准跳转。
- 不改变保存的阅读进度，除正常用户主动选择搜索结果所需的当前会话位置外，不额外写入历史。

**验收：** 一个章节含多个完全相同短语时，点选第二/末次命中会落在对应实例；覆盖中英文、空格规范化、跨页、单/双页/连续模式与无法映射回退；读进度、书签、标注回归通过。

### Task 4：仅在诊断证实漏章时修复 EPUB spine 覆盖

**文件范围：** 优先限定 `app/server/ai-fts.js` 与相应索引测试；不因搜索问题重写 EPUB 阅读器或 SQLite schema。

- 依据 Task 0 的反例修复已证实的 manifest/spine href 解析缺口，维护 ZIP 安全解包现有限额（entry 数、单项/总解压大小、压缩比）、路径规范化与包内路径边界。
- 仅索引 OPF spine 引用的可读章节，非 spine 图片/导航/脚注资源不得误当正文；href 解码和相对路径解析必须防止 `..` 逃逸 ZIP 根。
- 对坏 XML、缺失 item、非法 href 以章节级受控错误处理；明确区分“书合法但部分章节跳过”与“整个 OPF 无法解析”，不得静默声称完整索引。
- 不在每次搜索时扫描 EPUB 原文件；仍使用预建 FTS 索引。需要重建时由现有索引生命周期显式触发、可取消/受锁保护/原子发布，并确认不破坏 AI 共用索引。
- 若 Task 0 无法复现章节缺漏，本任务不改生产提取器，只保留回归夹具和覆盖验收。

**验收：** 全 spine 覆盖计数与 fixture 预期一致；恶意 ZIP/path、资源限额、坏 OPF、缺章节测试通过；原 AI 检索与索引管理回归通过。

### Task 5：安全回归、设备性能验收与打包门禁

**文件范围：** 搜索相关 Node/DOM/Playwright 测试、`docs/FNOS_DEVICE_ACCEPTANCE.md`、现有 FPK 构建流程。

- 完整执行 `npm test`、`npm run check`、相关 Chromium Playwright suite，覆盖书籍归属、Gateway、索引权限、AI 隔离、书签/标注和 reader lifecycle。
- 准备合成长书负载（至少数百章节、首/中/末章不同命中密度、低命中 query），比较首屏及续页耗时、候选数、SQL 计划和 RSS。记录真实基线与目标设备规格；任何放宽预算必须有实测与用户复核，不在此阶段隐性加大全局上限。
- 检查 API 与浏览器网络轨迹：只访问本地搜索 API，不访问 AI/provider、外网或其他书籍；测试日志不含正文、snippet、path/query/cursor。
- FPK 仅在代码阶段获准、回归通过且版本策略确认后构建。设备验收记录 x86_64/ARM64 实际架构、Gateway 身份、授权目录、多用户隔离、冷/热搜索和索引更新场景；不能把本机模拟或打包通过记作 fnOS 实机通过。

**验收：** 所有回归 PASS；性能和资源数据可复现；攻击/滥用参数受控；FPK 内容、版本和哈希可核验；未实测设备项明确保持 pending。

## 5. 测试矩阵与完成定义

| 场景 | 必须证明 |
|---|---|
| 20 条以上命中，末段位于远端章节 | 首屏及时返回；连续续取可看到末段且顺序一致 |
| 首次命中之后超过 2,000 候选块 | 每次受预算约束；cursor 能推进到后续命中，不出现假终态 |
| 低命中/零命中且全书很长 | 不进行无界请求；预算耗尽时仍能续取；最终才显示真正无结果 |
| 同块多个命中、跨块 overlap | 页边界不丢失同块命中，去重稳定，无重复结果 |
| 同章短语出现多次 | 结果 locator 与点击实例一致，而非跳至首次出现 |
| EPUB spine 变体与坏包 | 章节覆盖正确；路径、ZIP 炸弹和坏 OPF 保持安全受限 |
| 用户/书/query/scope/索引变化 | 每页重新授权；cursor 不能跨上下文复用；旧请求不能污染 UI |
| AI 与普通阅读回归 | 搜索无 provider/AI 路由调用，不改变阅读、AI、索引、标注及书签功能 |

只有当可访问授权书籍范围内的匹配能完整续取，章节缺口被诊断并修复或排除，点选定位准确，单请求工作有界，所有隐私与跨用户测试通过，且 FPK/设备状态如实记录时，才能宣布此项完成。
