# 首行缩进：调研与改造计划（2026-10-02）

## 1. 问题

截图（桌面双页）里同一章的段首缩进不一致：第一段约缩进 3 个字，其余段落约 2 个字；拖动“首行缩进”滑块后，有的书变、有的书不变，有的居中/落款行反而被缩进。设置本身也不符合阅读软件习惯：0～4 字、步长 0.5（1.5 字、2.5 字没有意义），而且叫“首行缩进”却不能真正做到“对齐无缩进”。

## 2. 现状（代码）

- 设置：`textIndent` 0～4，步长 0.5，默认 2（`reader/settings.js`、`core/user-state.js`、服务端 `storage.js` 同样按 0.5 取整）。
- 生效方式：`styles.css` 一条规则 `.article .epub-chapter p, li { text-indent: var(--reader-text-indent) }`，再给 `li / blockquote p / 居中 / .no-indent` 设 0。
- 书自带的 CSS 原样内联进页面（`epub.js inlineResourceRefs`），不做作用域隔离。
- TXT / Markdown 不在 `.epub-chapter` 里，**缩进设置对它们完全无效**；MOBI/AZW3 转成 EPUB 后走 EPUB 路径。
- 划线定位 = 章节内的 DOM 节点路径 + 文字偏移（`highlights.js serializeDomRange`）。**任何修改正文文字或包裹节点的做法都会让已有划线错位**，修正只能通过样式完成。

## 3. 抽样调研

本机现有真实书《剑来 1-42册.epub》（474 个章节文件、17 万段）：

| 现象 | 结果 |
| --- | --- |
| 书 CSS `p { text-indent: 2em }` | 有，正文靠它缩进 |
| 书 CSS 中刻意不缩进的类 | 27 条：`p.desc-6`、`p.end`（落款）、`.cp`、`.vernote`（注释，带左内边距的悬挂缩进）、`div.logo`、`h3.head` 等，全部 `text-indent: 0` |
| 段首全角空格 `　` | 0 段 |
| 段首 `&nbsp;` | 15 段 |
| `<p>` 内用 `<br>` 分行（诗句） | 42 段（`p.vol-text`） |

结论与常见中文电子书的几种排版方式：

1. **靠 CSS 缩进**（如上）：`.cp`、`p.end` 这类选择器的优先级低于我们的 `.article .epub-chapter p`，所以**书里刻意不缩进的注释、落款、简介被我们强行缩进了 2 字**；反过来，书里写了更高优先级的选择器、行内 `style`、`!important` 时，我们的设置又**完全不起作用**。
2. **靠段首全角空格 `　　`**（TXT 转制的 EPUB、网文最常见）：缩进 = 空格 + 我们的 2em，于是变成 4 字；选“无”时仍有 2 个空格，做不到对齐。
3. **段首 `&nbsp;`/半角空格**：宽度随字体变化，形成截图里“第一段多缩进一点”这类不齐。
4. **诗词、引文、注释、落款、居中标题行、图片说明、表格**：本该保持原书排版，不应套正文缩进。
5. **西文书**：首段不缩进、后续段缩进，或段间空行不缩进。

阅读软件的通行做法（凭对 legado 等开源阅读器与微信读书的了解；网上未搜到权威说明）：正文段落统一由阅读器排版——去掉原有段首空格后按设置重新缩进（legado 的“段首缩进”就是 0～4 个全角空格），非正文结构保持原样。微信读书的正文同样统一为固定缩进。

## 4. 目标行为

- 设置改为离散五档：**无（对齐）· 1 字 · 2 字 · 3 字 · 4 字**，默认 2 字；手机和桌面都用分段按钮，不再用滑块。
- “字”= 当前正文字号的一个汉字宽（1em），随字号变化。
- **正文段落**：不论原书用 CSS、全角空格还是 `&nbsp;` 缩进，实际显示的缩进都**恰好**等于所选档位；“无”时首字与其他行左对齐。
- **非正文**（居中/右对齐行、诗词分行、悬挂缩进的注释、列表、引文、表格、图注、只有图片的段落、书中明确设为不缩进的少数类）：保持原书样式。
- TXT 跟随同一设置；Markdown（文档类）保持不缩进。PDF 不适用（设置在 PDF 中隐藏，现已如此）。
- 已有划线、书签、阅读进度、AI 取证全部不受影响（不改动正文文字和节点）。

## 5. 方案

### 5.1 渲染时给段落分类（只加属性，不改文字）

在章节插入页面后、分页测量前（与 M4 的 `data-text-script` 同一位置），对章节内的块级文本元素（`p`，以及直接装文字的 `div`）逐个判断：

1. 读取原书计算样式（此时我们的缩进规则不参与）：`text-align`、`text-indent`、`padding-left`、是否含 `<br>` 分行、是否只有图片、是否在 `li / blockquote / table / figure` 内。
2. 统计本章段落的“样式签名”（类名 + 对齐 + 原缩进）。占正文绝大多数的签名视为**正文**；与正文签名不同、且原书明确设为 `text-indent: 0` 或悬挂缩进的少数类视为**刻意例外**。
3. 段首空白：测量段首全角空格/`&nbsp;`/半角空格的**实际像素宽度**（用 Range 取首字前空白的宽度），记到段落上。
4. 结果写成属性：`data-zs-para="body|keep"`，正文另加行内变量 `--zs-lead: <px>`。

### 5.2 样式

- 删除现在对所有 `p` 的一刀切规则。
- 正文：`[data-zs-para="body"] { text-indent: calc(var(--reader-text-indent) - var(--zs-lead, 0px)) !important; }`——用负缩进抵消段首空格，最终缩进恰好是 N 字；`!important` + 属性选择器保证压过书里的高优先级规则和行内样式。
- 例外：不设缩进，完全由原书 CSS 决定。
- 分类前的极短时间内用书的原样式，分类与分页测量在同一帧前完成，不会闪动或分页错乱。

### 5.3 设置与数据

- `textIndent` 取值改为整数 0～4；旧值迁移：四舍五入（1.5→2、2.5→3），客户端与服务端同一规则。
- 设置面板：“首行缩进”改为五段按钮“无 · 1 · 2 · 3 · 4”；排版预设（紧凑/标准/宽松）不再改缩进。
- TXT：同样分类（TXT 的段落几乎都是正文，段首全角空格最常见）；Markdown 不缩进。

### 5.4 调研工具

把本次的抽样脚本整理成 `scripts/survey-paragraph-indent.js`，可在 NAS 书库目录上运行，统计每本书属于哪种缩进方式，用来验证分类规则、发现新的特殊排版。截图里那本书若方便，请告诉我书名或放一本到测试书库，我把它加入验证。

## 6. 验证

- 新建一组测试 EPUB/TXT 夹具，覆盖：CSS 缩进、全角空格缩进、`&nbsp;` 缩进、行内样式、高优先级选择器、书内 `!important`、悬挂缩进注释、居中/右对齐、`<br>` 诗句、`div` 段落、西文首段不缩进。
- E2E：每种夹具在 0～4 五档下测量正文首字相对段落左边缘的偏移 = N × 字号（±1px），例外段落的偏移与原书一致；桌面单/双页、滚动、手机分页都测。
- 回归：已有划线在改造前后位置不变；分页页数与翻页对齐不受影响；全量单元 + E2E。

## 9. 执行记录（2026-10-02，完成）

实施中的新发现：**阅读器只保留章节 `<body>`，书自带的样式表从未进入页面**。所以此前所有书都是“无样式正文 + 我们一刀切的 2 字缩进”，居中/右对齐的类、注释的悬挂缩进、刻意不缩进的段落全都丢失；“原书”档若不处理就没有意义。

- **设置**：“首行缩进”改为分段按钮“原书 · 无 · 1 · 2 · 3 · 4”，放在排版预设下方（不再折叠在“自定义”里）；值为 `'book'` 或整数 0～4，旧的半档四舍五入（客户端 `normalizeTextIndent` 与服务端同规则）。
- **原书排版（仅版式）**：从书的样式表（`<link>` 与 `<head>` 中的 `<style>`，含 `@media` 内规则）只抽取 `text-indent`、`text-align`，以及同时设置了 `text-indent` 的规则里的左外/内边距（悬挂缩进），保留 `!important`，用 `:where(#article .epub-chapter)` 作用域（不增加优先级），放在 `<head>` 的单个 `<style id="zsBookLayout">` 中，绝不插入章节内部（划线按章节内节点路径定位）。字体、颜色、页边距等仍由阅读器主题决定。
- **段落分类**（新模块 `reader/paragraphs.js`）：章节挂载后、分页测量前读取书的实际版式；按“原缩进 + 左缩进”统计正文主样式（以字数加权），主样式与带段首全角空格/`&nbsp;` 的段落为正文；居中/右对齐、含 `<br>` 的诗句、悬挂缩进、首字前有图片或浮动元素、列表/引文/表格/图注内的段落，以及与正文样式不同的少数类保持原书样式。只写 `data-zs-para="body"` 与 `--zs-lead`（em），不改文字和节点。
- **样式**：正文 `text-indent: calc(N - lead) !important`，因此无论原书用 CSS、空格还是 `&nbsp;`，首字都恰好在 N 字处；正文两端对齐，例外段落用原书对齐。字体更换后重新测量（测量期间我们的规则让位）。
- **TXT**：不再当 Markdown 解析——每行一段（此前小说类 TXT 的多行会被合并成一个大段）、“第N章/卷/回”“序言/后记”等行渲染为标题；段首空格转为该段的“原书”缩进（避免两端对齐把空格拉宽），设置为数字时统一缩进。Markdown 不缩进。
- **调研脚本**：`node scripts/survey-paragraph-indent.js <书库目录>` 统计每本书的缩进方式与例外规则。
- **测试**：新增夹具 `e2e-indent.epub`（CSS 缩进含注释/简介/落款/居中/诗句、全角空格、`&nbsp;`、行内样式、书内 `!important`、`div` 段落、西文无缩进六章）与 `e2e-indent-novel.txt`；`e2e/paragraph-indent.spec.js` 在原书与 0～4 各档逐段测量首字位置（误差 ≤0.1 字：两端对齐会把段首全角空格各拉宽约 0.03 字），验证例外段落不动、悬挂与居中保留、TXT 分段与标题、Markdown 不缩进、改缩进后划线位置不变；服务端测试覆盖 `'book'` 与半档迁移。
