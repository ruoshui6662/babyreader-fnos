# 书库整理与分类链路修复

日期：2026-09-22。用户已授权审查、调研并修复；本文件记录本轮实施边界和验证。

## 已确认的问题

1. `organization.js` 的平铺分支只传 books，不传 library/scope/order，因此“全部书籍”显示整理按钮，却永远不会创建拖拽项。真实浏览器复现：点击整理后 `.library-reorder-item` 数量为 0。
2. 服务端 GET 用 resolver 补全新扫描书籍，PUT 却按磁盘上的原始顺序校验。初次整理未分类时，UI 提交两本书，而原始 unassignedOrder 为空，API 返回 400。分类内存在离线记录时也有同类不一致。
3. 原模型没有独立的全书架顺序，前端无法通过现有集合顺序表示全书架拖拽。
4. 新建分类成功后仍停留在原视图，用户不能就地添加书籍；picker 每次加入成功后销毁，连续加入流程中断，多个加入按钮可同时发送同一 revision。原生弹窗式隐藏错误提示也难以定位失败。
5. 拖拽结束先 clear 再读取 activeId，焦点恢复丢失；移出目标仍保留上一个候选目标。整理开关还出现在不允许修改的源目录视图。

单次加入接口本身未发现必现失败；本轮针对可证明的入口、连续添加、过期 revision 和导航问题修复，不能据此断言用户 NAS 上的所有添加失败都有同一原因。

## 分类拖拽与删除入口修复（2026-09-22）

- 根因：分类导航的排序监听只接受 `[data-reorder-handle]` 上的 pointerdown，分类名称按钮没有被视为拖动区域；自然地直接拖分类名称时不触发排序。另一个问题是分类名称、文字“删除”和独立手柄挤在同一导航行，窄屏/管理态下相互争用空间。
- 桌面端允许直接拖动分类标签主体，删除按钮明确排除在拖动起点之外；移动端维持长按手柄触发，不扩大触屏误触面。保留键盘排序及现有 revision-aware API。
- 横向分类栏增加拖动时的左右边缘自动滚动，便于分类数量多时调整位置。
- 删除操作改为紧凑 SVG 垃圾桶图标按钮，保留 `aria-label` / `title`；触屏尺寸不低于 44px，并采用轻量 hover/focus/destructive 状态，不改删除 API 和确认流程。
- 新增真实 API 浏览器回归：分类主体拖动并刷新后保持顺序、边缘自动滚动、删除图标语义/尺寸/布局；移动端长按回归保持通过。
- 验证：`npm test` 238 通过、5 个平台条件跳过；`npm run check` 与 `git diff --check` 通过；`npm run test:e2e` 默认套件 86 通过、10 跳过，组织专项 8 通过。FPK 已重打为 1.1.7，5,426,469 bytes，SHA-256 `08419640b100d0c8840b406481a048d7e0d99aca5c095d16d6c887ed24ce5f7f`；包内拖拽修复与源码一致。fnOS 真机尚未验收。
