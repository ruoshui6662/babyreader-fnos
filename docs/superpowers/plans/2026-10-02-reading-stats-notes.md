# 书库 · 阅读统计 · 笔记：规划（2026-10-02，待确认）

参考：用户提供的 `zhen_shu_reader_ui_demo.html`（仅作布局与样式方案参考）。目标：书库页左侧加入“书库 / 阅读统计 / 笔记”三栏导航；阅读统计按周、月归类，展示每日阅读时长、每本书阅读时长、最近笔记；笔记以“每本书一份笔记文档”的卡片呈现，可打开、导出，并能生成好看的图片卡片。整体沿用现有样式。

## 1. 现状（代码核实）

| 需要的数据 | 现状 |
| --- | --- |
| 阅读时长 | **完全没有记录**。进度只存“最后一次的百分比与时间”（`reading-state.json` → `books[id].progress`）。 |
| 读完的书 | 可由进度推断（≥ 98%），但没有“读完时间”。 |
| 笔记 | EPUB/TXT 划线与想法（`books[id].highlights`，含 `createdAt`、章节 `chapterHref`、颜色、想法）；PDF 标注（`books[id].pdfAnnotations`，含页码与时间）。都在每个用户自己的 `reading-state.json` 中。 |
| 导出 | 已有：单本 EPUB 笔记 Markdown（`reader/actions.js`）、PDF 笔记 Markdown（`reader/pdf-notes-export.js`）。没有汇总、PDF、图片。 |
| 书库页 | 渲染在阅读区 `#article` 内（`library/view.js`、`organization.js`），顶部是全局顶栏；整理视图使用 history state 记录路由。手机端已有 ⋯ 菜单、长按操作单。 |

结论：笔记部分可直接基于已有数据；**阅读统计必须先新增“阅读时长记录”**，统计只能从功能上线之日开始累积（历史时长无法补回，界面会说明）。

## 2. 开源方案调研（要点）

- **KOReader 统计插件**：用 SQLite 按“每页停留时长”记录，并设上下限（太短的翻页不计、停留过久按上限计，以排除离开设备的时间），据此汇总每日、每本书的时长。思路可借鉴：**只计“正在读”的时间，并对空闲封顶**。（据对 KOReader 源码的了解；本次检索只找到基于其 SQLite 数据做统计看板的文章，如 [Kindle/KOReader 阅读统计看板](https://scour.ing/p/https://aacevski.com/blog/kindle-reading-stats-dashboard)，未找到官方文档。）
- **Readest**（Foliate 的重写版）：阅读统计仍在规划中（[Readest](https://github.com/stevendong/readest)），说明 Web 阅读器里做时长统计主要难在“如何判断在读”。
- **微信读书**：读书时长按日累计、周/月报、书籍时长排行；笔记按书汇总，可生成书摘卡片分享。本规划的形态主要参照它和 demo。
- 图表与图片：不引入第三方库（应用的 CSP 只允许本地脚本），柱状图用 SVG/CSS 绘制、跟随主题；图片卡片用 Canvas 2D 自行排版生成 PNG；PDF 导出用浏览器打印（“另存为 PDF”）配合打印样式。

## 3. 设计方案

### 3.1 导航（只在书库页出现，阅读页不变）

- **桌面（≥ 900px）**：书库页左侧窄栏，三项：书库、阅读统计、笔记（图标 + 文字，选中项为品牌橙色淡底，同 demo）；窄窗口只显示图标。
- **手机**：书库页底部三栏标签（同微信读书），阅读时隐藏。
- 路由：`?view=stats` / `?view=notes`，配合 history，刷新与返回键可用；整理视图原有路由不受影响。
- 顶栏、配色、圆角、卡片风格沿用现有书库（深色 / 浅色 / 护眼三主题都适配），不照搬 demo 的白色主题。

### 3.2 阅读时长记录（新数据，S0）

- **判断“在读”**：已打开一本书，页面可见、窗口在前台，且最近 3 分钟内有阅读动作（翻页、滚动、选字、点击）。每 15 秒检查一次，满足条件计入 15 秒；超过空闲上限不再累计（参照 KOReader 的封顶思路）。
- **按“本地日期 + 书”累计**，每 60 秒、切到后台、关闭页面时上报；离线或请求失败时暂存在浏览器里，下次补报。
- **服务端**：新接口 `POST /api/reading-time`（批量，按用户隔离；校验日期格式、单次秒数不超过实际流逝时间、单日每本书不超过 24 小时，防止异常数据）；存为每用户单独文件 `reading-stats.json`（不写进 `reading-state.json`，避免频繁重写含全部划线的大文件）。
- **读完**：进度首次达到 98% 时记录 `finishedAt`；已经读完的旧书以最后进度时间补记。

### 3.3 阅读统计页（S2）

按 demo 布局，结合现有数据：

1. **周期切换**：本周 / 本月（分段按钮），左右箭头查看上一周、上一月。
2. **指标卡片**（4 张）：本期阅读时长（对比上一期 ±%）、读过的书（本期有阅读时长的书数）、读完的书、新增笔记（划线 + 想法 + PDF 标注）。
3. **每日阅读时长**柱状图：周视图 7 根、月视图按天 28–31 根；悬停/点按显示当天时长与读了哪些书；顶部显示总时长与日均。
4. **书籍阅读时长排行**：封面、书名、本期时长、阅读进度条；点击打开该书。
5. **最近笔记**：书名、摘录（划线颜色）、想法、时间；点击跳到原文位置。
6. **空状态**：还没有记录时，说明“从现在开始记录阅读时长”。

### 3.4 笔记页（S3）

1. **笔记文档卡片**：每本有笔记的书一张卡（封面、书名、笔记数、想法数、最后更新），另有一张“全部笔记汇总”；可搜索笔记内容或书名，可按最近更新/笔记数排序。
2. **笔记文档阅读视图**：书的信息头（封面、作者、阅读时长、进度）；笔记按章节（EPUB 用目录章名，PDF 按页）分组，每条显示划线文字（颜色条）、想法、时间；每条可“跳到原文”“复制”“生成卡片”。
3. 想法的编辑、删除沿用阅读页现有的编辑器与接口，不另建“自由笔记”（见 §6 待确认）。

### 3.5 导出与图片卡片（S4）

- **Markdown**：单本（复用现有格式并统一 EPUB/PDF）与全部汇总。
- **PDF**：笔记文档视图的打印样式（A4、封面信息、章节分组），用浏览器“打印 → 另存为 PDF”，不引入库。
- **图片卡片**（Canvas 绘制 PNG，下载或长按保存）：
  - 单条书摘卡：摘录 + 想法 + 书名作者 + 日期 + 枕书标识，提供 3 种配色（浅色、护眼、深色）；
  - 整本笔记长图：书的信息头 + 全部（或选中的）笔记，超长自动分多张。
  - 中文字体用阅读器已有的字体，生成前等待字体加载，避免缺字。

## 4. 分阶段计划与验收

每阶段：实现 → 单元/DOM 测试 → Playwright（桌面 + 手机视口）→ 全量回归 → 提交；阶段结束给你看截图再进入下一阶段。

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| **S0 阅读时长记录** | 前端计时器（可见性、空闲 3 分钟封顶、批量上报、失败补报）；服务端接口、校验、`reading-stats.json`；读完时间 | 单元：日期/秒数校验、跨日、并发累加、按用户隔离；E2E：打开书阅读并翻页 → 统计接口有对应书的时长；页面隐藏或空闲超过 3 分钟后不再增加；刷新/关闭不丢已读时长 |
| **S1 导航框架** | 桌面左侧栏、手机底部标签、`?view=` 路由与返回键；三个页面骨架 | 书库原有功能（整理、长按、导入、扫描、搜索）全部回归通过；刷新停留在当前栏目；手机返回键行为正确；阅读页不出现导航 |
| **S2 阅读统计页** | 统计接口（周/月、上一期对比、每日、每书）；指标卡、柱状图、排行、最近笔记、空状态 | 用构造数据验证周/月边界（周一起始）、跨月、对比百分比、日均；柱状图与数值一致；三主题与手机布局无溢出；点击排行打开书、点击笔记跳到原文 |
| **S3 笔记页** | 笔记汇总接口（每本书计数、最近更新；单本完整笔记含章节名）；卡片列表、搜索排序、文档视图 | EPUB 与 PDF 笔记都正确分组；章节名与阅读页目录一致；1000 条笔记时列表与搜索不卡顿；跳到原文位置正确 |
| **S4 导出与图片** | Markdown（单本/全部）、打印 PDF、单条书摘卡与整本长图 | 导出内容与页面一致；PNG 中文无缺字、长文自动换行与分页；三种配色；手机可保存 |
| **S5 收尾** | 性能（大量笔记/长期数据）、无障碍、文档、真机验收清单 | 全量回归；真机检查手机底部标签、图片保存、打印 |

## 5. 不做 / 暂缓

- 历史阅读时长无法补回（功能上线前没有记录）。
- 不做跨用户排行、社交分享链接（只生成图片，由用户自己保存分享）。
- 不引入图表库或截图库。

## 6. 待确认

1. **“在读”判定**：最近 3 分钟有阅读动作才计时，是否合适？（越短越保守，越长越容易把发呆算进去）
2. **月视图柱状图**：按天（28–31 根，推荐）还是按周（4–5 根）？是否需要“年视图”？
3. **“已读书籍”指标**：同时显示“读过的书（本期有时长）”与“读完的书（进度 ≥ 98%）”，还是只显示其一？
4. **笔记范围**：笔记文档只由划线与想法自动生成（推荐），还是也要支持 demo 里的“新建笔记”（不依附原文的自由笔记，需要新的存储与编辑器）？
5. **图片卡片**：单条书摘卡 + 整本长图两种都做，还是先做单条书摘卡？

## 7. 用户决定（2026-10-02）

1. “在读”判定：最近 **3 分钟**内有阅读动作才计时。
2. 月视图：**按天 28–31 根柱**（不做年视图）。
3. 笔记文档：**只由划线和想法自动生成**，想法在阅读页编辑；不做自由笔记。
4. 图片卡片：**单条书摘卡 + 整本长图**都做。
5. 指标卡（未单独询问，按推荐）：同时显示“读过的书（本期有阅读时长）”与“读完的书（进度 ≥ 98%）”。

## 8. 执行记录

### S0 阅读时长记录（完成）

- 前端 `reader/reading-timer.js`：打开一本书、页面可见、最近 3 分钟内有阅读动作（翻页/滚动/滚轮/点按/按键/选字）时，每 15 秒累计一次（长时间休眠只算一次间隔）；按本地日期 + 书累计；每 60 秒、页面隐藏、关闭时上报（`keepalive`）；未被服务端接受的时长按用户存在浏览器 `localStorage`，下次补报；服务端拒收（400）的数据不再重试。不要求窗口获得焦点（手机与双屏阅读），只要求页面可见与最近有动作。
- 服务端 `reading-time.js` + `UserStorage.addReadingTime / getReadingTime`：校验日期真实、在 2000 年之后且不超过服务器日期一天（东时区）、书 ID、整数秒；每本书每天最多 24 小时；按用户的独立文件 `reading-stats.json` 与独立队列（多设备同时上报都会累加），不改写 `reading-state.json`。接口：`POST /api/reading-time`、`GET /api/reading-time?from=&to=`。
- 读完时间：进度首次达到 98% 时记录 `finishedAt`，之后回退再读完不覆盖。PDF 进度现在也带百分比（页码 / 总页数），书库能显示 PDF 的阅读进度，读完的 PDF 也能被识别。
- 测试：`tests/reading-time.test.js`（校验、跨日、并发累加、24 小时上限、按用户隔离、读完时间）；`e2e/reading-time.spec.js`（阅读时累计、空闲后停止、页面隐藏不计、回到书架不计、上报失败后刷新补报、非法上报被拒）。

### S1 导航框架（完成）

- `library/shelf-nav.js`：书库页的“书库 / 阅读统计 / 笔记”导航。桌面为顶栏下的左侧栏（200px，窗口窄于 900px 时只显示图标，72px）；手机（及窄于 640px 的窗口）为底部三栏标签；阅读页不显示。
- 路由：`?view=stats` / `?view=notes`（书库无参数），切换用 history push，刷新与返回键保持栏目；整理模式原有路由不受影响（其返回处理只在整理视图在页面上时生效）。从某栏目打开书，返回时回到该栏目。
- 统计与笔记页暂为标题与说明，S2/S3 填充。
- 手机整理模式底部操作条移到标签栏上方。
- 测试：`e2e/shelf-nav.spec.js`（桌面侧栏与宽度、窄窗口仅图标、URL/刷新/返回、阅读时隐藏、返回原栏目、手机底部标签）。PDF 封面测试改为先滚动到对应书（封面按需在接近视口时生成，侧栏让每行书变少）。

### S2 阅读统计页（完成）

- 服务端 `reading-stats-summary.js` + `GET /api/stats?range=week|month&anchor=YYYY-MM-DD&tz=`：周（周一开始）或自然月、上一期；本期阅读时长、读过的书（有时长）、读完的书（`finishedAt` 落在本期）、新增笔记（划线/想法/PDF 标注的 `createdAt`）；每日时长及当天各书；书籍时长排行（含进度、封面、是否仍在书库）；最近 10 条笔记；最早记录日期。ISO 时间按浏览器时区偏移换算为本地日期。
- 前端 `library/stats-page.js`：本周/本月分段与前后翻期（不能翻到未来）；4 张指标卡及与上一期对比（持平显示“与上周持平”，上一期为 0 显示“上周没有记录”）；每日柱状图（周 7 根、月按天，今天高亮，点柱显示当天时长与各书）；书籍时长排行（点击打开书）；最近笔记（点击打开书并跳到该笔记）；“全部笔记”进入笔记页。没有记录时说明从何时开始记录。手机单列、无横向溢出。
- 测试：`tests/reading-stats-summary.test.js`（周/月边界、闰年二月、上一期、时区换算、汇总/排行/最近笔记、空数据）；`e2e/stats-page.spec.js`（周/月切换、柱数、翻期、选柱说明、排行打开书并返回统计页、手机无溢出）。截图在 `docs/screenshots/stats/`（以 `ZHENSHU_SCREENSHOT_DIR` 运行该测试生成）。

### S3 笔记页（完成）

- 服务端 `epub-toc.js`（只解压 container/OPF/nav/NCX 读目录，24 本 LRU 缓存）、`notes.js`；`GET /api/notes`（按书汇总）、`/api/notes/search?q=`（最多 200 条）、`/api/notes/:bookId`（按原书章节名与阅读顺序排序；PDF 用“第 N 页”）。
- 前端 `library/notes-page.js`：书卡网格 + “全部笔记汇总”卡；搜索（划线、想法、书名，命中高亮）与排序（最近更新 / 笔记最多 / 书名）；笔记文档 `?view=notes&doc=<书 id|all>`，按章节分组，每条可“跳到原文”“复制”，从阅读页返回回到文档；刷新保持文档。
- 测试：`tests/notes.test.js`、`e2e/notes-page.spec.js`；截图在 `docs/screenshots/notes/`。全量回归：单元 692 通过；E2E 209 通过（1 个 PDF 页面颜色用例满载时偶发失败，单独重跑通过）；整理 E2E 25 通过。

### S4a 单条书摘卡片（完成）

- `library/note-card.js`：Canvas 自绘，不引入库。模板 书页（纸纹、纤维、双细框、大引号水印、朱印“枕书”）/ 素笺（朱红侧栏线、每行格线、划线色想法标记）/ 墨夜（深色、金色细框与角标、描边印章）；字体 思源宋体 / 霞鹜文楷 / 朱雀仿宋（画前用 `document.fonts.load` 只加载用到的字）；比例 3:4（1080×1440）、1:1（1080×1080）、16:9（1920×1080，右侧书栏）；显示开关 想法 / 书名 / 日期 / 书封；选择记在本机。
- 排版：中文禁则（句读不在行首，开引号不在行尾）、两端对齐、按框自动选字号；最小字号仍放不下时截断并提示。日期写作“二〇二六年十月二日”。没有封面的书画成线装书（装订线 + 竖排题签）。
- 入口：笔记文档每条“卡片”；阅读页桌面批注编辑框“生成卡片”（带上未保存的想法）；手机批注气泡“卡片”。保存：手机支持系统分享时走分享，否则下载 PNG（`枕书-书名-日期-时间.png`）；桌面可“复制图片”。
- 测试：`e2e/note-card.spec.js`（模板/字体/比例/开关/记忆/下载 PNG 尺寸、禁则与截断、阅读页入口、手机无溢出、样图生成）。样图在 `docs/screenshots/cards/`。

### S4b 多条书摘 / 整本长图（完成）

- 笔记文档（单本书）新增“生成长图”：进入选择模式，每条笔记前加勾选框，默认全选（即整本书），点笔记可取消；底部浮条显示“已选 N / M 条”、全选/全不选、取消、生成长图。全部笔记汇总不出长图（S4c 用 Markdown / PDF）。
- `renderNotesLongImage`：宽 1080，沿用三种模板与字体；页头为封面（无封面画线装书）、书名、作者、“N 条书摘 · M 条想法”；按原书章节分组（章节名两侧短线），每条书摘左侧一笔划线色（素笺为格线），想法、日期可开关，条目之间三点分隔；页尾朱印与生成日期。超过 8000 像素时在两条书摘之间分页，续页顶部写“《书名》 · 续”，每页底部页码；单条最多 90 行引文、36 行想法，超出以省略号结尾。
- 对话框与单条卡片共用（`openNoteCardShell`）；长图不显示比例；多张图手机一次分享、桌面依次下载（`枕书-书名-书摘长图-日期-时间-序号.png`）。

## 9. S4 导出与图片卡片：调研与方案（已确认）

### 9.1 参考

| 产品 / 项目 | 做法 | 可借鉴 |
| --- | --- | --- |
| 微信读书 | 长按划线 → 书摘卡片；笔记可导出；卡片带书名、作者、封面与日期 | 从“一条书摘”出发；书的信息放在卡片底部 |
| Readwise「Textshots」 | 同一条划线有 Pretty / Clean / Classic 三种风格，可切方形版本 | 少量（3 个）模板而非大量花样；方形适合图片社交平台 |
| 少数派《23 款文字卡片工具横评》、醒文、文字小卡等 | 模板 + 字体 + 背景色 + 显示/隐藏项 | 字体、背景、显示项可调，其余固定 |
| Vercel Satori | HTML/CSS → SVG，自带排版 | 需要完整 TTF/OTF 字体文件，中文字体 10MB 级，不适合 |
| modern-screenshot / dom-to-image | DOM → 图片（SVG foreignObject） | 需把字体内联为 data URL，分片字体很重；Safari 有兼容问题 |

### 9.2 技术选择：Canvas 2D 自绘（不引入库）

- 卡片排版用 JS 描述（边距、字号、行高、颜色），在 Canvas 上绘制，预览与导出是同一张画布，所见即所得；不受 CSP 限制，无第三方依赖。
- 中文换行自己实现：逐字测量；行首禁则（，。、；：？！”」』）》等不出现在行首）、行尾禁则（“「『（《 不在行尾）；英文按单词换行，超长单词断开；可选两端对齐。
- 字体：用应用已带的分片字体（OFL 许可，可用于导出图片）。绘制前对卡片上的全部文字执行 `document.fonts.load(字号 字体, 文本)`，只下载用到的分片，保证不缺字。
- 尺寸：导出宽度 1080px；高度按内容自适应，也可选 3:4（1080×1440）或方形（1080×1080，内容过长时自动缩小字号）。长图超过约 8000px 自动分成多张（手机浏览器画布有大小上限）。
- 保存：电脑下载 PNG；手机优先用系统分享（Web Share，可直接存相册或发微信），不支持时下载，或显示图片供长按保存。

### 9.3 风格（3 个模板 × 字体 × 配色）

1. **书页**（默认）：暖白纸色，宋体正文，左上大号引号，底部书名、作者、小封面与日期，右下角“枕书”。最接近纸书书摘，适合分享。
2. **简洁**：白底（或深色底）、左侧一条与划线颜色一致的色条，正文宋体，信息行用细小字号。适合技术类、长摘录。
3. **夜读**：深色底、浅色字，色条为划线颜色。深色模式下的默认。

- 字体可选：思源宋体（默认，端正）、霞鹜文楷（手写感，书摘卡片常用）、朱雀仿宋（古籍感）。卡片上所有文字用同一套字体，保证不同设备导出一致。
- 配色：纸色（浅 / 护眼米黄 / 深），强调色跟随划线颜色。
- 显示项：想法、书名作者、日期、封面可开关。

### 9.4 卡片范围

- **单条书摘卡**：笔记文档中每条“生成卡片”；阅读页的划线气泡里也加入口。
- **多条 / 整本长图**：笔记文档进入“选择”模式勾选若干条（可全选）→ 生成长图：顶部书的信息（封面、书名、作者、笔记数），按章节分组列出所选笔记。全选即“整本笔记长图”。
- **全部笔记汇总**不做图片（太长），用 Markdown / PDF 导出。

### 9.5 Markdown 与 PDF

- Markdown：单本（统一 EPUB/PDF 格式：书名、作者、章节标题、摘录引用、想法、时间）与全部汇总（按书分节）。
- PDF：笔记文档的打印样式（A4、页眉书名、章节分组、避免一条笔记跨页断开），用浏览器“打印 → 另存为 PDF”。

### 9.6 分步与验收

| 步骤 | 内容 | 验收 |
| --- | --- | --- |
| S4a 卡片引擎 + 单条书摘卡 | Canvas 排版（禁则换行、自适应高度、方形缩放）、字体按需加载、3 模板 × 3 字体 × 配色、预览对话框、保存/分享 | 单元：换行禁则、长英文、超长文字缩放；E2E：生成 PNG 尺寸正确、各模板像素抽查（背景色/文字非空）、不缺字（字体加载完成后再绘制）；手机可保存 |
| S4b 多条 / 整本长图 | 笔记文档选择模式、长图排版、超长自动分页 | 选 1/多/全部条数正确；分页后每张不超过上限；章节分组与文档一致 |
| S4c Markdown 与 PDF | 单本/汇总 Markdown、打印样式 | 导出内容与页面一致；打印预览无截断、每页有书名 |

### 9.7 用户确认（2026-10-02）

- 风格：书页分享要“稍微有一点艺术质感”——纸纹、细框、印章式落款，仍以文字为主。
- 字体：思源宋体、霞鹜文楷、朱雀仿宋（均为 SIL OFL 1.1，可免费商用；生成的图片不受字体协议限制，只是不可单独出售字体文件）。
- 不放二维码。
- 比例：16:9、3:4、1:1。
