# 精确搜索命中提示实施计划

## 目标与当前证据

搜索结果已能通过 `findSearchTextRange()` 找到具体 DOM Range，并通过 `navigateToSemanticTarget()` 翻到正确位置；但 `navigateToSearchResult()` 把 `reader-search-target` 加到 Range 的段落/章节祖先，导致整块文本闪烁。目标是只提示命中词句的实际字形区域，保持既有定位与阅读模式。

## 安全边界

- 仅改阅读器搜索临时提示、对应 CSS 和测试；不改搜索 API、FTS 索引、书籍文件、AI、书签或持久划线数据。
- 不用 `surroundContents`、`innerHTML` 或文本节点包裹改写正文；用只读 Range 几何绘制无文本、不可交互、`aria-hidden` 的独立瞬时层。
- 复用严格的 offset/snippet 歧义校验。无法确认具体命中时不高亮第一个候选，保留现有失败提示。
- 翻页、重搜、切书、重绘或计时到期必须撤销旧提示；异步跨章节跳转必须防止旧请求覆盖新请求。永久标注层和点击交互不受影响。
- 工作树已有未提交的搜索与其他功能修改；只对本任务相关文件做局部补丁，不清理、不混入提交、不打包。

## Task 0：基线与契约冻结

1. 运行现有 DOM 搜索回归，记录通过/失败。
2. 核对 `search.js`、`pagination.js`、`document.js`、`styles.css` 的定位、重绘与测试入口。

验收：当前行为与根因有证据；未改运行代码。

结果：完成。改动前 `node --test tests/dom-regression.test.js` 为 112/112 通过；根因是把匹配 Range 的祖先段落设为 `.reader-search-target`。

## Task 1：精确提示的失败测试

1. 更新 DOM 测试：跳转仍选中正确 Range，但不再给段落加类；精确层与错误定位的清理可观察。
2. 更新 Chromium E2E：提示矩形落在匹配文本的 `Range.getClientRects()` 上，明显小于段落；重复命中、跨章节、单/双页/滚动模式不回退。

验收：新断言针对旧实现失败，说明测试能抓住整段闪烁。

结果：完成。新增 DOM 精确层断言先在旧代码上 3/3 失败；Chromium 测试验证命中矩形宽度和重复词的真实 Range 几何。

## Task 2：瞬时 Range 提示层

1. 搜索跳转成功后，按 Range 的文本片段矩形绘制独立 `pointer-events:none` 层；跳转和布局就绪后测量，不碰永久标注层。
2. 层只使用主题 token，浅色/深色可读，支持 `prefers-reduced-motion`；计时清理、上限防御及过期回调隔离。
3. 对搜索文字节点遍历排除提示层，避免新层影响后续匹配。

验收：精确命中字形被温和提示，整段/整页不变色；不阻挡选中、点击和翻页。

结果：完成。独立无文本、不可交互、`aria-hidden` 层按 Range rect 绘制；主题色与减少动画偏好已覆盖。首次 Chromium 回归暴露关闭搜索面板会重置令牌，已改为在关闭后取得跳转令牌。

## Task 3：生命周期与回归

1. 搜索新结果、切书、章节/正文重绘、主动翻页撤销旧提示；跨章节竞态用递增 token 丢弃过期跳转。
2. 运行 DOM、Chromium 搜索 E2E、相关静态检查和全量单测；记录真实结果。

验收：无旧提示残留、无错误命中高亮、原搜索与标注功能维持；如需实机验证则列为发布前手测，不宣称已做。

结果：完成本地验证。搜索 E2E 10/10、阅读器 E2E 47/47、DOM 回归 113/113、全量 Node 单测 254 通过/5 跳过、结构检查和 `git diff --check` 通过。未打包、未在 fnOS 实机测试；发布前需实机核对不同字体/缩放下的命中矩形与暗色主题。
