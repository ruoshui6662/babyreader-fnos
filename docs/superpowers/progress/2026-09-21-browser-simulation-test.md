## 测试中发现并处理的问题

### 1. 回归测试状态重置竞态

部分旧测试先打开带有历史进度的 EPUB，再重置服务端进度并刷新。旧页面的延迟进度保存可能在重置后到达，导致后续用例从第 2 章开始。

处理方式：调整 `highlights`、`persistence`、`viewport` 测试的初始化顺序，改为先重置服务端状态，再打开书籍；不修改产品运行逻辑。相关专项 17/17 通过。

### 2. 文本书返回入口体验待优化

浏览器模拟发现 Markdown/TXT 阅读页的顶部“返回书库”按钮当前按 `isEpub` 隐藏。文本书可以通过其他入口回到书库，但顶部导航缺少一致的返回路径。

建议后续将显示条件从“仅 EPUB”调整为“存在当前文档”，并补充文本书返回书库回归用例。本次不擅自修改，避免扩大当前刷新修复边界。

### 3. 章节切换存在短暂异步等待

章节切换和 EPUB 解析期间按钮会短暂禁用，等待解析完成后恢复。功能最终正常，但等待期间用户反馈不够明确。

建议后续保留按钮位置并显示轻量“正在打开”状态，避免用户误以为点击无效。本次作为体验问题记录，不纳入刷新修复。

### 4. AI 外部服务未做真实供应商联网验收

本次浏览器环境验证了 AI UI、请求边界、流式状态、配置和本地模拟响应；未使用真实 API Key 进行外部供应商连通性测试。真实 DeepSeek/OpenAI 连接仍需在 fnOS 真机配置后单独验收。

## 结论

浏览器刷新回到书库的问题已通过 EPUB 和 Markdown 两类书籍验证修复。当前固定夹具全量回归无失败；剩余事项为文本书顶部返回入口、章节切换等待反馈，以及真实 AI 供应商联网验收。
