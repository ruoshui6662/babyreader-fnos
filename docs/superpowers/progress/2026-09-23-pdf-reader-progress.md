## Frozen Contracts for Later Tasks

- PDF content requests use only the current 64-hex `bookId` at `/app/babyreader-fnos/api/books/:bookId/content`; no filesystem path or arbitrary URL is accepted.
- PDF responses use `application/pdf`, same-origin/private no-store headers, and at most one `bytes` range. Valid ranges return `206`; unsatisfiable ranges return `416` with `Content-Range: bytes */<size>`; multipart ranges are rejected. Ordinary full GET remains available for compatibility. `HEAD` returns headers only if the chosen PDF.js loading path requires it; PDF.js itself must be verified before implementation.
- `pageIndex` is a zero-based integer in stored progress, API locator, and search results; displayed page numbers are `pageIndex + 1`.
- Search hit locator shape follows the spec: `{ version: 1, type: 'pdf', pageIndex, textOffset, quote }`, with `textOffset` measured in UTF-16 code units in normalized page text v1 and quote/context bounded by existing search limits. Keep normalizer version in PDF index metadata; include the exact PDF.js version in the parser fingerprint so a parser upgrade invalidates only PDF indexes. If the page text layer cannot verify the hit, navigate to the page and report page-only localization; never highlight the whole page as a verified match.
- PDF feature gate: `BABYREADER_PDF_ENABLED` accepts the existing boolean convention (`1`, `true`, `yes`, `on`), defaults to off, and is exposed as `features.pdfReader`; final FPK startup enables it only after Task 5 acceptance. Acceptance builds may opt in through that variable. Rollback sets it off and leaves existing book/index/progress data untouched.
- Parser, canvas, range, page, text, and time ceilings are deliberately not frozen yet; values need synthetic-fixture benchmarks and a target-device memory/latency baseline.
