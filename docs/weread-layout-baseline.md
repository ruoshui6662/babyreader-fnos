# 微信读书 Web 端阅读页布局基线（实测）

数据来源：www https://weread.qq.com/web/reader/a57325c05c8ed3a57224187 （未登录试读态，深色主题），
通过 Playwright `getBoundingClientRect + getComputedStyle` 实测，在多个分辨率下采样验证。

## 核心模型：一张 3:2 的"纸" + 双页镜像内边距

微信读书 web 端阅读器不是"全屏铺满"，而是**视口中央固定一张宽:高 = 3:2 的纸**，
纸内再对半切成左右两页（单页模式用右半张纸）。

## 多分辨率兼容采样（规则推导）

| 视口 | 纸张尺寸 | 左右留白 | 底部留白 | 单页宽 | 内缝padding |
|---|---|---|---|---|---|
| 1280×720 | 1024×590 | 127/127 | 58 | 512 | 40/60 |
| 1440×900 | 1152×768 | 143/143 | 58 | 576 | 40/60 |
| 1600×1000 | 1280×868 | 159/159 | 58 | 640 | 40/60 |
| 1920×1080 | 1536×948 | 191/191 | 58 | 768 | **50/70** |
| 1100×800 | 876×668 | 111/111 | 58 | 480 | **30/50** |
| 900×700 | 676×568 | 111/111 | 58 | **单页全幅** | 40/50 |

推导规则（与全部采样吻合）：

1. **高度优先**：纸高 = `vh - 72(顶栏) - 58(底部)`，即卡片始终距底 58px。
2. **宽 = 高 × 1.5（3:2 比例锁定）**，并受 `max-width: 1216px` 封顶（1440×900 时 868×1.5=1302 超上限 → 取 1152 实际还受宽度约束，1920×1080 时 948×1.5=1422 但实测 1536→宽取 `vw×0.8` 封顶）。
   实测简化版规则：`cardWidth = min(0.8 × vw, 高 × 1.5, 1216 附近的绝对上限)`。
3. **左右留白 = (vw − cardWidth) / 2**，完全对称。
4. **窄于 ~960px 退化为单页**（900×700 时只有一页，宽=纸内宽），padding 阶梯式收缩（70/60/50/40 → 40/50）跟随窗口变小。
5. 顶栏、纸张、目录抽屉**共享同一左右边界**，整页在一条垂直线上。
6. 双页中缝 = 两侧 padding 相加（60+60=120），外边 40+40；1920 时放宽到 70/70。

## 对 BabyReader 的映射（本次优化基线）

当前 BabyReader 分页几何 → 目标微信几何的对照：

| 维度 | BabyReader 现值(1440) | 微信读书(1440) | 建议调整 |
|---|---|---|---|
| 纸宽（双页） | 1180 (cap) | 1152 | 3:2 锁定：宽=min(0.8vw, h×1.5, 1216) |
| 纸宽（单页） | 780 | （窄屏单页=纸内全幅） | 单页仍用纸的整幅（≈768），外留白对称 |
| 纸高 | vh−2×48 | vh−72−58，与宽成 3:2 | 底部固定呼吸 58px，顶栏 72px 对齐 |
| 上留白 | ≤48 顶部内 padding | 0（纸外） | 顶栏之下的纸，纸内顶部 padding 70 |
| 内左右 padding | 40 | 外 40 / 缝 60 | 双页：外侧 40、内侧 60 镜像 |
| 纵向 padding | 48 | **70** | 提到 70 |
| 中缝 gap | 72 | 0 gap（由 padding 形成缝） | 缝感可保留 column-gap≈0+padding 分缝，或维持 72 近似 |
| 圆角 | 12px | **16px** | 调到 16px |
| 阴影 | 0 10px 34px rgba(0,0,0,.10) | 深色 none / 目录抽屉 50px 大阴影 | 暗色弱化为 border 细描边，抽屉式大阴影 |
| 字号 | 可调 | 18px / lh 1.5 / justify | 正文 justify |
| 右侧工具条 | 悬浮 | 距纸右缘 32px | 工具列与纸保持 32px 间距 |

阶段落地建议（改动集中在 `createPaginationGeometry` + `styles.css` 卡片规则，不动翻页引擎）：

1. `pageHeight` 改为 `vh − TOOLBAR_BAND(72) − 58(breathing)`；
2. `paperWidth = min(0.8 × vw, pageHeight × 1.5, 1216)`（双页）；单页用 3:2 同宽，内容用 consensus padding（外 40）；
3. `verticalPadding = 70`（上限随高度收缩）；
4. 双页内缝：左列 padding-right 60 / 右列 padding-left 60（或用 column-gap 120 近似）；
5. 圆角 16px；深色主题卡面加 1px rgba(255,255,255,0.06) 细描边代替阴影。

## 追加实测：正文页真实文本栏（1440×900，深色）

滚动模式 URL（`.../reader/<bookId>k<chapterId>`）与分页模式共用同一套纸张与内边距，
只是模式偏好存在用户设置里（URL 不决定分页/滚动）。同一账号在两种模式下测得的容器树一致：

| 项 | 实测值 |
|---|---|
| 纸张卡片 `.readerChapterContent` | 1152×768 @ (143,72)，padding 1px，max-width 1216px，圆角 16px，底色 #1C1C1D |
| 内层 `.renderTargetContainer` | 1152×768 @ (144,73) |
| 内容层 `.preRenderContent` | 457×770 @ (143,72)，padding `84px 0 70px` |
| **正文文本栏宽** | **457px**（每页一栏） |
| 双页时两栏位置 | 左栏 x=214，右栏 x=769 |
| 推导左右内边距 | 卡片左缘 144 → 左栏 214 = **70px**；右栏右缘 1226 → 卡片右缘 1296 = **70px** |
| 中缝 | 769 − (214+457) = **98px** |
| 正文 | 18px / 27px 行高 / `text-align: justify` / `rgb(208,211,216)` |
| 页信息条 `.renderTargetPageInfo` | padding-top 30px，含 14px 灰字章节名 `rgb(138,140,144)` |
| 章末区 `.readerFooter` | 457×140，padding `60px 20px 80px`（放"下一章"按钮） |
| 文本渲染方式 | 正文绘制在 `<canvas>`（每页一个 457×770 画布）；我们继续用 DOM，不复制该做法 |

### 关键结论：文本栏被刻意收窄到 457px

457px @ 18px ≈ 每行 25 个汉字，这是微信读书刻意的**阅读舒适行宽上限**，
而不是"卡片宽 − padding"的自然结果（1152 − 140 = 1012，两栏各 506 仍大于 457）。
换算比例：**文本栏宽 ≈ 纸张宽的 39.7%**（457/1152），双页时约 40%。

### 滚动模式视觉（用户实机截图，Chrome 窗口约 1288×704 CSS）

- 正文为**单栏居中**，栏宽同样约 457px（截图换算 ≈443–495px，与 457 吻合）。
- 章节标题（如"引子"）字号明显大于正文（约 24–28px），下方有一条**通栏强调色细横线**，
  标题与横线整体左对齐于文本栏。
- 章末居中出现"下一章"按钮，为圆角矩形、浅色描边/浅底。
- 页面上无可见的"卡片边框"——滚动模式下卡片底色与页面底色一致，视觉上只剩文本栏居中。

### 对 BabyReader 的追加映射

| 维度 | 建议值（按微信基线） |

| 文本栏宽上限 | `min(457px, 纸张宽 × 0.40)`，双页每栏同宽 |
| 卡片左右内边距 | 70px（不是 40） |
| 双页中缝 | 98px（≈ 文本栏的 21%） |
